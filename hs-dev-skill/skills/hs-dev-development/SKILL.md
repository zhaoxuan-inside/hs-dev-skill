# G 开发与验证

产出符合当前业务、工程和质量要求的真实修改及同版本验证证据。

与用户问答及展示方案时，先遵循[统一表达规范](../../references/questioning.md#面向用户的表达)。

## 进入与活动选择

先核实当前诉求与已有有效成果，仅补当前缺口。按下列活动选择当前对象；不明位置时才查[活动索引](../../references/activities.md)，不加载整个catalog或阶段正文。使用公开命令 `template --activity ID [--output ID]` 只取得当前活动或输出的具体问题、证据与通过标准。模板留空、来源缺失或最坏情况未处理不能作为已完成。

## 必要输入

- 当前任务范围、必要规则与决定、契约、质量标准及授权。
- 实际代码与调用方、已有修改、配置、验证入口和恢复依据。

## 本阶段的判断重点

- 复用前期认知和仍有效的输入；先查当前实现，再只询问新差异或必要决定，不重问产品愿景。
- 明确可观察预期后小步实现与验证；缺陷先建立现象与原因证据，优化固定可比基线与保持项。
- 代码和文档取得有效锁并复核基线后才写入；同步受影响契约、资料和用例，禁止用代码反改需求。
- 实际运行正常及风险相关异常检查，尽早验证跨模块和真实依赖；替身、沙箱与实际目标分别说明。
- 关键变更需要独立评审视角；发现规则或架构缺口返回负责阶段，不让实施者凭方便自行裁决。
- 权限、缓存、异步或跨层变更按[跨边界工程审查](../../references/engineering-review.md)检查消费者、依赖和失效生命周期；用实际反例约束实现，避免只追加成功路径或继续扩大全局职责。
- 面向生产的改动按[生产开发与上线证据](../../references/production-readiness.md)选择真实后端、并发与故障验证，复核命令确实运行了必要用例；缺少目标环境证据时限定结论并继续独立开发。

## 最低达成标准

- 实际差异在范围内，业务路径已实现，代码、契约、资料和验证对应同一有效版本。
- 适用行为、工程和集成检查有真实结果；失败、跳过、未验证和局限可见，一致性提交后最后解锁。

## 执行与交接

完整执行[共同工作循环](../../references/cycle.md)，不另设本阶段的锁、授权或提交流程。查证与阅读遵循[信息规范](../../references/information.md)，主动追问、回答后反例与独立多角色讨论遵循[讨论规范](../../references/questioning.md)。

代码修改留在工程源目录；同步的现行规则归 `hs-dev/project/`，本次变更和交付结果归 `hs-dev/deliveries/`，执行与验证证据由程序保存在 `hs-dev/execution/`。

失败不能通过删断言、放宽预期或重跑碰运气掩盖；外部变化或中断时停止受影响写入，保留状态供恢复。
