# 测试设计与验证

负责用例构建、行为及真实集成证据，核对受影响任务、方法和调用链的覆盖。简单内部方法可通过调用链间接验证，不要求每个方法单独建测试；不能以全 Mock 证明真实集成，不能以覆盖率或测试数量证明行为正确。

沿用当前过程选定的活动、对象与上下文，不扩大任务范围。只有专业缺口会影响结果时才反馈缺失决定或证据，由当前过程选择活动；不读取整阶段资料或重复加载已有约束。

测试服务于当前过程：设计阶段形成用例和验证计划，实施阶段执行适用检查，调试阶段提供复现及回归证据，重构阶段核对行为等价，验收阶段核验指定材料。纯评估不自动创建测试或修改代码；人工确认由统一模块处理。

## 执行清单

- [ ] **核实基线与预期**：定位本次目标、需求/契约、实际变更、相关调用链及项目测试约定；记录源版本或内容摘要和已有失败。预期应来自已定规则或明确要求保留的行为，不能直接照抄实现推导断言。规则缺失或冲突返回当前过程澄清。
- [ ] **选择适用检查**：依据下表及当前活动清单选择风险相关用例，说明覆盖对象、输入/初始状态、预期和断言。复用有效用例，避免仅匹配实现文字或重复测试框架本身；低影响修改不为凑数量新增测试，不把局部任务升级为全项目审计。
- [ ] **核实运行条件**：确认实际命令、依赖、配置、数据及外部服务；区分真实资源与替身，优先使用隔离数据和既有测试设施。按当前授权执行，不默认使用生产资源、发送外部消息、安装新服务或清除用户数据；必要环境缺失明确报告，不擅自改换测试目标。
- [ ] **执行与取证**：先运行最能验证本次变化的检查，再按调用链和集成风险扩展必要回归。新增缺陷回归或 TDD 用例时，条件允许应确认其在修复前因目标行为失败、修复后通过；环境或语法错误不算有效行为失败。纯计划不记执行通过。
- [ ] **分类失败并处理**：区分产品/实现缺陷、测试预期错误、环境故障、既有失败和非确定性问题；保留命令、退出码及相关输出，不靠反复重跑、删除断言或放宽预期使结果变绿。证据不足不猜根因；需要诊断或超出当前修复授权时交回当前过程。
- [ ] **交付与停止**：给出检查范围、结果、真实/模拟边界及未覆盖风险。修复后重跑受影响检查；已通过且无新变更或未决风险时不机械重复或扩大测试。结果绑定实际源版本，后续相关源改变时复核受影响证据，不把旧结果冒充新版本结果。

## 检查选择

每行按条件选择，不是必做流水线。活动标准由当前过程选择，本表不新增阶段或门禁。

| 当前问题 | 检查方法与依据 | 按需资料 |
|---|---|---|
| 规则、边界或状态转换需验证 | 选择正常、边界、拒绝及适用异常场景，用可观察结果和不变量断言；缺陷回归应能区分修复前后行为 | [E5 用例](../../share/workflow/e_engineering_preparation/e5_test_cases/checklist.md)、[G2 切片验证](../../share/workflow/g_implementation_integration/g2_slice_verification/checklist.md) |
| 接口或数据交换变化 | 核对输入输出、错误、空值和适用的访问/重复语义；用契约检查验证双方一致，不以替身自洽证明服务端符合契约 | 当前对象契约；缺口涉及标准时读 [E2 接口](../../share/workflow/e_engineering_preparation/e2_interface_contracts/checklist.md) |
| 数据库、文件、网络或平台适配变化 | 对实际受影响边界执行集成验证，核对配置、依赖、副作用和清理；真实服务不可用时说明替代范围及未验证部分 | [G3 集成](../../share/workflow/g_implementation_integration/g3_incremental_integration/checklist.md) |
| 用户路径或跨模块切片变化 | 选择代表性端到端成功及相关失败路径，核对各边界实际协作；界面及设备行为由对应专业技能协同，复用同一证据 | 当前功能与交互契约、G3 已选条目 |
| 并发、重试、超时或恢复变化 | 按已定语义验证重复、取消、中断、部分失败和恢复后结果；需要时采用可控调度或故障注入，不依靠任意等待碰运气 | [E4 运行与失败](../../share/workflow/e_engineering_preparation/e4_runtime_failure_design/checklist.md) |
| 重构或共享依赖变化 | 沿受影响调用链选择行为保持及回归检查，核对边界和副作用；现状与要求冲突时交回当前过程，不把偶然行为自动固化为需求 | G3 已选条目、当前保留行为约束 |
| 语言、资源或质量风险 | 执行项目适用的类型、静态、构建或资源检查；性能/安全等检查须对应明确目标和条件，不以构建通过证明功能或质量全部达标 | G2 已选条目、当前质量契约 |
| 安装、启动、交付或恢复是本次目标 | 对实际目标产物演练适用路径，记录环境和数据条件；源码测试通过不证明分发包可用，不擅自对真实用户数据做破坏性恢复试验 | [H2 交付与恢复](../../share/workflow/h_delivery_feedback/h2_delivery_recovery_verification/checklist.md) |

## 证据与结果

每项记录 `对象/用例／依据／环境与源版本／命令或操作／预期与实际结果／状态／证据及未决项`。状态使用“通过、未通过、不适用、未验证”；不适用说明理由，跳过、超时、取消或环境阻塞不能记通过。自动命令记录时间、退出码和必要输出，人工操作记录步骤及观察；简单任务直接回复，不强制新建报告。

Mock、夹具、模拟器、真实资源和实际设备的证据分别说明，日志不包含凭据或不必要的用户数据。非确定性失败须保留首次失败和相关运行条件，说明重跑结果及未解决风险，不能用一次重跑成功抹去失败。

结论限定于实际覆盖的行为、版本和环境；未测试不宣称达标。测试通过不等于产品完整、用户价值已验证或人工验收通过。发现范围外问题记录影响和位置，交由当前过程决定，不自动扩展实现或发布。
