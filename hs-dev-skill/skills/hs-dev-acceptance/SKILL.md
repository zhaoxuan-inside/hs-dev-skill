# 交付核验

从本次验收范围、绑定材料和证据开始；核验已有活动只读取其已选清单，不重走产生材料的过程。发现问题后只将相关项送回负责过程。需要确认时读取[统一验收协议](../../share/core/acceptance.md)，按任务模式记录确认来源，不代签人工验收。

## 执行清单

- [ ] **确定核验基线**：核实本次对象、约定范围、适用清单、源版本、绑定材料、证据及已有确认。区分只读评审与受管验收登记；只读评审不创建任务、写入确认或自动修复索引。
- [ ] **选择适用项**：按下表选取当前需要的活动，复用有效上游和确认，不重做产出流程。缺少关键范围或标准时交由用户或负责过程明确，不自行缩减验收分母。
- [ ] **逐项对账**：将每个适用标准关联到实际产物及证据，核对对象、内容版本、条件与结论一致，检查遗漏、孤立项及过期证据。材料存在、构建成功或测试全绿不能代替全部标准的核验。
- [ ] **补足专业证据**：按实际缺口调用 testing 核验行为与集成、governance 核验适用的一致性，或相应领域技能核验专业标准，复用同一证据。补测必须在授权范围内；不自动修复产品、访问生产资源或执行破坏性恢复演练。
- [ ] **汇总并处理确认**：按统一协议登记适用标准的结果与证据；不适用给出理由，缺失、过期或未执行的证据保持未验证或未通过，不能记 PASS。向审阅者展示具体范围、主要材料、检查摘要、风险和待审重点；按当前模式处理确认，不代签、不重复请求仍有效的确认。
- [ ] **完成或交接**：完成前复核当前内容、依赖、证据与确认仍有效，适用项通过、阻断清零且确认责任满足后才标记完成。缺陷返回 debugging，需求变化返回 discovery/continuity，保留行为的结构调整返回 refactoring；只交接受影响项及下一动作，不自动创建新任务或重启全流程。

## 输出

给出本次范围、逐项结果、证据位置与有效性、确认状态、阻断及下一动作。只读评审直接回复，不强制生成报告；受管验收使用统一协议规定的结果和材料记录，不另建竞争性清单或确认机制。专业核验结论与真实人工确认分别呈现。

## 上下文边界

只读本任务命中的活动清单，并按目标定位代码与证据；不扩读相邻活动或整阶段资料。安全与范围遵循主入口；涉及写入时按需读取[执行协议](../../share/core/execution.md)，需要验收时读取[验收协议](../../share/core/acceptance.md)。
