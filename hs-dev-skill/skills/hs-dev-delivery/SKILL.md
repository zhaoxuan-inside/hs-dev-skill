# H 交付反馈

使接收方知道交付了什么、在什么条件下可用、哪些限制仍存在以及接下来如何处理。

与用户问答及展示方案时，先遵循[统一表达规范](../../references/questioning.md#面向用户的表达)。

## 进入与活动选择

先核实当前诉求与已有有效成果，仅补当前缺口。按下列活动选择当前对象；不明位置时才查[活动索引](../../references/activities.md)，不加载整个catalog或阶段正文。使用公开命令 `template --activity ID [--output ID]` 只取得当前活动或输出的具体问题、证据与通过标准。模板留空、来源缺失或最坏情况未处理不能作为已完成。

## 必要输入

- 本次范围、真实产物与版本、有效规则和决定，以及当前验证和评审结论。
- 目标环境、使用/部署说明、恢复条件、真实反馈及接收责任。

## 本阶段的判断重点

- 从实际对象核对范围、覆盖与版本，不以文档存在推定实现；缺陷和优化分别建立可判断基线。
- 沿最终交付路径执行适用安装、配置、启动与核心任务，必要恢复在授权隔离范围验证。
- 按当前授权和责任区分业务、使用、运行和维护接收视角；高影响分歧独立分析后交叉复核。
- 接受前复核前置依据、实际检查、评审、未决和原始反馈；复用有效决定，不因阶段切换再问相同问题。
- 反馈区分事实、缺陷、需求变化和建议，按影响返回负责活动并提供首个下一动作。

## 最低达成标准

- 交付对象、版本、支持条件、实际结果和限制可追溯；设计、实现、验证、交付与部署状态分开。
- 接受或拒绝有真实来源和具体范围；剩余问题有影响、责任归属与下一动作，最后一致性提交并解锁。

## 执行与交接

完整执行[共同工作循环](../../references/cycle.md)，不另设本阶段的锁、授权或提交流程。查证与阅读遵循[信息规范](../../references/information.md)，主动追问、回答后反例与独立多角色讨论遵循[讨论规范](../../references/questioning.md)。

本次产物、版本说明、接受决定与后续动作进入 `hs-dev/deliveries/`；影响长期使用的现行说明同步到 `hs-dev/project/`，实际运行与验收证据由程序保存。

没有真实环境或恢复证据时保持对应未验证，不能把计划当上线或容量证明；交接完成不代表原任务完成。
