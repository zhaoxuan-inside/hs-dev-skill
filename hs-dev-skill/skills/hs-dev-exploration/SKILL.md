# 只读探索

从问题涉及的入口、代码符号或文档章节开始，沿直接调用、数据流和必要约束读取。现有证据能够回答问题时停止扩展。只有用户明确要求对照某项工程标准评估时，才读取该项活动清单；普通解释不读取 workflow。直接返回结论和位置证据，不创建任务、快照、PRD或提交，不触发阶段验收。

## 探索清单

- [ ] **锁定问题**：明确需要解释或评估的对象、范围及预期回答，复用已有上下文；不因理解现有工程而启动逆向建档或产品发现。问题存在会改变结论或范围的歧义时澄清，继续不依赖答案的定位。
- [ ] **选择追踪路径**：行为问题追入口、调用和状态转换；数据问题追来源、转换、存储及消费者；架构问题追依赖、进程和外部边界；设计评估对照已知目标和约束。只读取回答问题所需关系，有证据缺口才扩展，不将局部问题变成全项目审计。
- [ ] **核对证据**：分别标明实际实现、文档声明、已有运行结果及推测。代码和文档不一致时指出位置及影响，不自动认定哪一方代表正确需求；仅凭静态代码不能宣称已验证运行行为。复用结果前核对相关内容和版本，证据不足明确未知。
- [ ] **按需专业协作**：只加载问题涉及的领域技能，并将只读约束传递给其分析。testing、governance 等不得因此自动补测、修复或刷新索引；命令执行前核实副作用，不修改源、受管索引、任务或外部状态。主入口允许的只读协调检查按其协议处理，不将其扩大为业务写入；需要有副作用的实验时先说明验证缺口，转入具备相应授权的过程。
- [ ] **回答并停止**：先给结论，再附必要的文件位置、调用/数据关系及未证实项。发现问题时报告依据、影响和建议，不自动修复；已有修改授权时按主入口切换负责过程，否则止于分析。证据已足够回答时结束，不额外生成报告、索引或验收材料。

## 输出要求

简单问题直接回答，复杂关系按需要使用简图或表格，不强制图示。无法访问或确认的路径如实说明，不把搜索未命中当作功能不存在；结论限定于实际检查的对象和版本。分析完成不代表工程通过验收，也不代替用户决定。

## 上下文边界

只读本任务命中的活动清单，并按目标定位代码与证据；不扩读相邻活动或整阶段资料。安全与范围遵循主入口；涉及写入时按需读取[执行协议](../../share/core/execution.md)，需要验收时读取[验收协议](../../share/core/acceptance.md)。
