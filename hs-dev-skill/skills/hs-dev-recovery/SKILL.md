# 快照与恢复

统一快照、changelog、冲突保护、完整恢复和保留清理。遵守[主入口](../../SKILL.md)及[专属协议](../../share/support/recovery.md)，不改变业务验收权限。

continuity 负责恢复任务上下文及组织下一动作，本 Skill 负责快照、操作恢复和恢复依据的专业执行；普通续做不自动回滚文件。仅分析恢复可行性时保持只读，不创建快照或清理历史。

## 执行清单

- [ ] **识别场景与范围**：核实工程根、工作区安全状态、task_id、操作标识、当前源版本及用户期望；区分快照准备、操作回滚、任务回滚、中断协调和保留清理。不从“继续”、超时或命令失败推断同意回滚。
- [ ] **检查恢复依据**：通过现有协调入口核实快照与日志归属、完整性、可恢复状态和目标路径；检查后续任务、编辑及冲突。快照过期、对象损坏或范围不明时停止依赖该依据的恢复，报告缺失条件，不手工猜测重建。快照正文及恢复历史不进入默认模型上下文，使用核验结果和必要摘要。
- [ ] **落实授权与冲突保护**：已有明确授权可沿用；范围扩大或覆盖后续工作需另行明确。操作回滚使用记录的后像检测冲突，不绕过拒绝；任务回滚恢复整个任务基线，不能假设具有相同的逐路径后像保护，必须先核对当前差异及后续编辑。发现无法解释的修改或无法证明其归属时不执行整体回滚。
- [ ] **调用正确入口**：按下表选择 CLI，并遵循[执行协议](../../share/core/execution.md)的锁、UUID/fence 和状态约束；具体参数以当前 CLI 帮助为准。不直接调用底层 restore、删除日志或手工标记 SAFE 来绕过协调。申请或撤销凭据不代表文件恢复完成。
- [ ] **核验恢复结果**：检查目标内容及新增/删除/移动的结果、任务与操作状态、索引发布和源摘要一致性，按影响执行必要行为验证。区分恢复命令结果、工作区安全及业务行为；恢复成功不自动证明旧测试或确认仍有效。中断或校验失败保留阻断和原错误，不继续业务写入。
- [ ] **交付并返回**：报告恢复对象、依据标识、实际范围、检查结果、冲突和未验证项；不输出快照正文或凭据。条件满足后由 continuity 返回负责过程继续，不能把恢复完成当作原任务完成或代签验收。

## 命令选择

命令均通过 `python <安装根>/hs-dev-skill/scripts/hs_dev.py --root <工程根> ...` 调用；下表是选择依据，不是必须顺序执行的流水线。

| 场景 | 命令与边界 |
|---|---|
| 为已存在任务保存恢复点 | `snapshot --task <task_id>`；会写入恢复记录并可能触发保留策略，不在只读咨询中运行。不要与底层自动快照重复创建 |
| 回滚特定修改操作 | `rollback <recovery_operation> --decision rollback`；标识来自恢复日志，不能与当前写入 UUID 混用。核实归属、可恢复性与后续冲突 |
| 回滚整个任务 | `task-rollback <task_id> --decision rollback`；会恢复整个基线，CLI 拒绝存在后续任务的情况，但此检查不能代替后续编辑核验。不作为操作回滚失败后的兜底 |
| 处理失联/中断所有者 | `recover-lock --decision continue` 或 `--decision rollback`；仅撤销旧凭据，仍须按状态继续核验及 reconcile/rollback，不能据此宣称内容已恢复或安全 |
| 接受授权范围内的现有修改并重新核验 | 依执行协议使用 `reconcile`，指定实际任务、活动和验证命令；这不是恢复前像，不得靠重建基线掩盖未解释漂移 |
| 执行保留策略 | `retention`；按实际配置和在用保护执行，不手工删除对象或引用。只在当前任务需要且允许清理时调用，不因加载本 Skill 自动清理 |

## 结果要求

区分“可恢复、不可恢复、存在冲突、已恢复且核验、恢复后待验证”等结论，附对象、依据、命令结果、证据位置及下一动作。未执行不能称恢复成功；无冲突不能单独证明授权充分。简单任务直接回复，不强制新建报告；失败时不扩大恢复范围、清理证据或自动发布。
