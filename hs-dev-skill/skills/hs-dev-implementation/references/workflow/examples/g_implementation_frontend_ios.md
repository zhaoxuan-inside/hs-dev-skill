# G 实现集成范例：iOS 草稿恢复

> 配套 [D iOS 架构范例](../../../../../share/workflow/examples/d_architecture_frontend_ios.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

输入过程中及时写入本地仓库；视图生命周期只触发状态刷新和调度机会，不承担唯一保存时点。后台同步遵守项目已选择且获授权的系统能力；重试保持幂等。后台执行机会不足时，本地内容仍可恢复，不能把系统后台调度保证为前提。

## G2/G3 验证

| 场景 | 通过结果 |
|---|---|
| 连续输入后立即切后台，再返回前台 | 已确认本地内容完整；界面刷新本地/同步状态，不把待同步误报为已同步 |
| 本地保存确认后系统挂起或结束进程，再启动 | 恢复最后一次已确认内容；后台任务未运行不导致草稿丢失 |
| 离线后恢复网络或重复调度同步 | 沿用同一 mutation ID 安全重试；仅在服务端确认后转为已同步 |
| 发生版本冲突 | 本地与服务端版本均可辨识和选择，不静默覆盖任一版本 |
| 键盘、动态字体、VoiceOver 或已启用的权限路径 | 编辑和状态反馈可操作、可感知；拒绝/撤销可选通知等能力不阻断本地保存 |

记录 iOS 版本、设备、授权/后台能力、网络条件和模拟器/真机结果。模拟器结果不证明真机后台调度；未执行的生命周期组合标为未验证。
