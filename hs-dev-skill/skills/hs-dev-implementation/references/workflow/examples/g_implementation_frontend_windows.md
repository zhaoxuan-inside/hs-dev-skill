# G 实现集成范例：Windows 草稿恢复

> 配套 [D Windows 架构范例](../../../../../share/workflow/examples/d_architecture_frontend_windows.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

窗口生命周期层把关闭/退出意图交给应用服务；应用服务读取本地写入状态后按已确认产品规则处理。待同步队列存于可跨进程重启恢复的位置。若产品支持托盘，窗口关闭与显式退出遵循各自已批准行为；UI 回调不实现同步协议。

## G2/G3 验证

| 场景 | 通过结果 |
|---|---|
| 本地写入尚未完成时关闭窗口 | 按产品决定阻止关闭或明确提示；不得报告已保存或丢弃未落盘内容 |
| 已保存但尚未同步时关闭并重新启动 | 本地草稿可恢复，队列继续安全同步，服务端确认前状态仍为待同步 |
| 多窗口编辑同一草稿 | 版本变化可见；本地与服务端内容均保留，冲突交给约定的选择流程 |
| 托盘关闭与显式退出（仅在支持时） | 两条路径按已批准规则执行；未启用托盘的构建不把该项列为通过 |
| 应用升级 | 在目标安装方式下保留原数据和待同步状态；升级失败按现有恢复机制处理 |

记录 Windows 版本、架构、安装/升级方式、用户权限和窗口/托盘配置。只对实际支持并测试的运行模式报告通过。
