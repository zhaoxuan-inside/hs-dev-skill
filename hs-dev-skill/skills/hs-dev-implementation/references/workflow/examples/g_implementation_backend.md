# G 实现集成范例：后端草稿同步

> 配套 [D 后端架构范例](../../../../../share/workflow/examples/d_architecture_backend.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

Handler 只校验并映射协议；服务层执行 mutation 幂等和版本条件；Repository 在同一事务/一致性边界读取版本并写入。过期基础版本返回冲突，存储异常不能伪装成冲突或成功。真实事务机制依项目数据库决定。实现以 [E 契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)为准，不在本范例中另定字段、认证或隔离规则。

## G2/G3 验证

| 场景 | 通过结果 | 证据重点 |
|---|---|---|
| 缺字段、无效版本或超长内容 | 返回稳定的输入错误；草稿内容和版本无副作用变化 | 请求、响应、写入前后状态 |
| 相同 mutation ID 重放 | 返回同一逻辑结果，只产生一次版本推进和业务副作用 | 两次响应、版本及副作用计数 |
| 两个请求基于同一旧版本并发写入 | 最多一个成功；另一个得到冲突及当前版本，成功内容未被静默覆盖 | 并发请求、结果、最终持久化版本 |
| 存储超时或事务失败 | 返回可区分的失败；不报告成功或业务冲突，部分写入按实际事务语义回滚/隔离 | 故障注入方式、服务响应、事务后状态 |
| 跨用户/租户访问 | 按已确认的身份和数据边界拒绝越权，合法主体仍可读写 | 身份夹具、拒绝响应及数据归属 |

记录数据库及版本、隔离/事务配置、并发方式、测试环境和实际结果。契约测试证明不了生产容量或可用性；未使用的认证或租户边界标为不适用并说明依据。
