# G 实现集成范例：macOS 草稿恢复

> 配套 [D macOS 架构范例](../../../../../share/workflow/examples/d_architecture_frontend_mac.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

窗口/文档层传递稳定草稿 ID；菜单、快捷键和窗口控件调用同一草稿服务。已确认内容及时写入本地仓库，不依赖后台或退出回调承担唯一保存责任。沙盒、文件授权等适配只在所选存储能力需要时触发，遵循项目已确认的授权行为。

## G2/G3 验证

| 场景 | 通过结果 |
|---|---|
| 关闭一个窗口但应用仍运行 | 该窗口草稿可按产品规则恢复；其他窗口状态不受影响 |
| 关闭最后一个窗口、显式退出及重新启动 | 各操作的产品语义一致；已确认本地内容可恢复，待同步状态不冒充已同步 |
| 菜单、快捷键和窗口控件执行保存/冲突操作 | 三种入口进入同一业务规则并呈现一致结果，不绕过版本检查 |
| 系统结束进程或后台后恢复 | 已确认本地内容保留；未确认写入不标为成功 |
| 项目实际使用的沙盒/文件权限被拒绝或撤销 | 按已定产品行为提示并安全处理；不因失败宣称写入成功或覆盖其他文件 |

记录 macOS 版本、CPU 架构、沙盒/授权状态、分发方式及实际操作结果。未实测的窗口生命周期和授权组合标为未验证。
