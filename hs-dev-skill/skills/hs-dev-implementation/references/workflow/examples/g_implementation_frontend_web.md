# G 实现集成范例：Web 离线草稿

> 配套 [D Web 架构范例](../../../../../share/workflow/examples/d_architecture_frontend_web.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

页面状态调用草稿服务；草稿服务先落本地仓库，再由同步协调器提交 API。组件不直接操作存储、不自行重试。跨标签页检测到版本变化时进入冲突状态，不能覆盖另一标签页或服务端版本；同步字段、冲突语义和结果状态沿用配套 D/E 契约。

## G2/G3 验证

| 场景 | 观察结果 |
|---|---|
| 输入后刷新或新开页面 | 最后一次已确认本地保存的内容恢复；状态区分待同步与已同步 |
| 浏览器存储写入失败或空间受限 | 编辑内容仍在当前界面，不能显示已保存；明确提示持久化失败和恢复条件 |
| 两标签页同时编辑 | 检出版本差异；本地与服务端内容均可辨识和选择，不静默覆盖 |
| 离线后恢复网络或请求超时 | 以同一 mutation ID 安全重试；结果未知期间保留草稿，服务端确认后才显示已同步 |

记录浏览器及版本、存储模式、离线/配额条件、执行步骤与实际结果；本范例给出判据，不声称已在任何浏览器通过。
