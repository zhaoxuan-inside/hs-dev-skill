# G 实现集成范例：Android 草稿恢复

> 配套 [D Android 架构范例](../../../../../share/workflow/examples/d_architecture_frontend_android.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

稳定草稿 ID 跨导航和重建传递；页面状态放在可恢复的应用状态层，本地仓库独立于 Activity 生命周期。后台队列采用项目已选机制表达持久性、约束和取消语义；不在 Activity 回调内承担唯一保存或同步。保存与冲突状态遵循共用 [D/E 契约](../../../../../share/workflow/examples/d_architecture_common.md)和工程准备范例。

## G2/G3 验证

| 场景 | 通过结果 |
|---|---|
| 系统返回、手势返回、旋转/配置变化及 Activity 重建 | 按已定产品规则导航；已确认本地保存的正文、草稿 ID 与版本恢复，不出现重复草稿或空白覆盖 |
| 本地保存确认后结束进程并重新启动 | 恢复最后一次已确认本地内容；未完成写入不显示为已保存 |
| 网络约束变化、离线后恢复、任务重试或取消 | 离线内容保留为待同步；安全重试沿用同一 mutation ID；取消只影响调度，不丢本地草稿 |
| 相关系统权限拒绝或撤销 | 按项目决定降级并提供可理解状态；不因可选能力失败清除已保存草稿 |
| 输入法、返回焦点或适用辅助功能操作 | 文字编辑、保存状态和冲突处理仍可操作，状态反馈可被目标辅助技术感知 |

记录 Android/API 与 target SDK、设备/厂商、电源策略、调度约束、权限状态及模拟器/真机结果。明确覆盖的组合；单一设备通过不代表所有 Android 设备或系统版本通过。
