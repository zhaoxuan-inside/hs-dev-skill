# G 实现集成范例：Linux 草稿恢复

> 配套 [D Linux 架构范例](../../../../../share/workflow/examples/d_architecture_frontend_linux.md) 和 [E 工程契约](../../../../../share/workflow/examples/e_engineering_preparation_draft_sync.md)。

## G1 实现边界

通过所选框架/平台 API 获取用户数据位置，不硬编码某一用户目录；按项目存储机制完成安全写入。显示协议、门户和通知位于可替换适配层，不作为保存和同步的强制依赖。关闭窗口/退出规则沿用已确认产品决定。

## G2/G3 验证

| 场景 | 通过结果 |
|---|---|
| 首次保存及目录权限不足 | 数据写入经确认的应用数据位置；权限不足时明确失败，不显示已保存，也不改写其他位置兜底 |
| 保存确认后关闭、退出或结束桌面会话，再启动 | 恢复最后一次已确认本地草稿；退出行为符合产品规则 |
| 离线、恢复网络及重复同步 | 草稿保持待同步直至服务端确认；重试安全且不产生重复副作用 |
| 桌面通知/门户缺失或不可用 | 核心保存和同步仍可用；相关可选 UI 能力给出降级反馈 |
| 支持的显示协议、桌面环境及安装包升级 | 每个已声明组合都能读写原数据并满足窗口行为；未覆盖组合单独标为未验证 |

记录发行版/版本、桌面环境、Wayland/X11、显示与文件系统权限、包格式及升级路径。验证报告只覆盖实测组合，不概括为“Linux 全平台通过”。
