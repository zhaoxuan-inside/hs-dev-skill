# R 技术评审

发现实现与约定的偏离，以及实现和验证可能共享的错误假设。

与用户问答及展示方案时，先遵循[统一表达规范](../../references/questioning.md#面向用户的表达)。

## 进入与活动选择

先核实当前诉求与已有有效成果，仅补当前缺口。按下列活动选择当前对象；不明位置时才查[活动索引](../../references/activities.md)，不加载整个catalog或阶段正文。使用公开命令 `template --activity ID [--output ID]` 只取得当前活动或输出的具体问题、证据与通过标准。模板留空、来源缺失或最坏情况未处理不能作为已完成。

<!-- hs-activity-nav:R:start -->
- `R1` 契约对照评审
- `R2` 分歧与异议处理
<!-- hs-activity-nav:R:end -->

## 必要输入

- 完整变更集、有效规则、契约与决定，以及实际用例和验证记录。
- 争议对象、各方依据、版本、实际责任和可裁决问题。

## 本阶段的判断重点

- 从完整变更识别新增、修改、删除与关联资料，未登记对象也必须解释，不能自行圈掉难审范围。
- 从原始规则提取独立场景，对照输入输出、权限、状态、不变量、错误及副作用；测试全绿不自动通过。
- 评审者实际独立分析，再与提供、消费或运行等相关角色交叉质疑；没有独立工具时说明降级局限。
- 事实争议用证据核实，取舍争议交有权者，执行问题回负责活动；结论绑定实际对象和内容。
- 相关机制按[跨边界工程审查](../../references/engineering-review.md)取独立反例；已修历史问题不得冒充现存漏洞，结构风险和未验证推演不得写成实证缺陷。

## 最低达成标准

- 每项相关变更有可定位结论、依据、偏离及下一动作；证据局限明确。
- 争议有裁决来源、回写和复核；未决或因内容变化失效的结论持续阻断相关接受。

## 执行与交接

完整执行[共同工作循环](../../references/cycle.md)，不另设本阶段的锁、授权或提交流程。查证与阅读遵循[信息规范](../../references/information.md)，主动追问、回答后反例与独立多角色讨论遵循[讨论规范](../../references/questioning.md)。

本次评审、偏离处置和分歧结论进入 `hs-dev/deliveries/`；规则或决定确需变化时回写 `hs-dev/project/`，逐项证据、对象版本和执行状态由程序关联。

缺少权威依据时不能默认代码或文档正确；评审通过不代替实际验证或交付接受，也不自动授权修改实现。
