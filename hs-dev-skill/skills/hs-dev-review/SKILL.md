# 技术评审与团队对齐

从本次变更集和受影响登记开始：评审包由 kernel ID 链与对象图从 diff 推导，不由评审者自行圈定范围。缺登记先返回对应活动补登记，不以口头描述或记忆替代对照物。

## 执行清单

- [ ] **生成评审包**：用 `kernel` 命令对账 ID 链，沿 `implemented_by` 从变更单元反查受影响行为内核，补齐契约、用例与相关决策，形成逐项对照清单。链条断裂（悬空引用、缺失实现绑定）本身就是评审发现，先登记再继续。
- [ ] **逐项对照契约**：比对实现与契约语义（输入/输出、错误、副作用、前置/后置条件）。发现偏离先分类：实现违背契约交 debugging；契约不再正确返回 E1/E2 更新契约并按 G4 同步；不默认代码正确，也不默认文档正确。
- [ ] **核对用例可判断性**：covered_by 用例应能判定偏离场景；未被覆盖的场景登记用例缺口，"测试全绿"不构成无偏离证据。
- [ ] **处理分歧**：对决策、契约或实现行为的异议按 R2 登记——绑定对象 ID 与内容摘要，事实分歧以证据复核，取舍分歧升级为 decision-record（记录被否方案），执行分歧移交负责活动；未决异议保持阻断可见。
- [ ] **留痕与交接**：结论绑定内容摘要进入任务材料；阻断项写明责任活动与下一动作。评审通过不代替人工验收（H3），不解除 E9/G4 机械门禁；绑定的代码或契约随后变化时评审结论失效，重审受影响项。

## 输出

逐项对照结论、偏离清单（缺陷或契约变更）及移交对象；分歧的登记、裁决与回写结果；未决异议及其阻断范围。只读评审直接回复；受管评审使用统一协议的检查结果与材料记录。
