# Linux 客户端框架

与 [客户端框架基础](../hs-dev-framework-client-base/SKILL.md)配合使用，只补充 Linux 平台的应用架构差异。界面和输入体验由[前端基础](../hs-dev-frontend-base/SKILL.md)及 [Linux 前端特性](../hs-dev-frontend-linux/SKILL.md)负责；服务端结构由后端框架入口负责。

## Linux 框架特性

- **目标环境。** 明确发行版、桌面环境、最低系统库、CPU 架构及显示协议支持范围。不要将某一个发行版或 GNOME/KDE 的行为假定为所有 Linux 环境的共同能力。
- **显示与桌面协议。** 检查 X11/Wayland 目标和窗口管理器差异；系统门户、文件选择、屏幕共享、通知等通过标准接口或可替换适配边界接入。
- **应用进程与用户数据。** 定义单实例/多实例、退出和后台运行策略，遵循用户数据与配置目录约定；系统服务或开机启动仅在明确需要时引入。
- **依赖与分发。** 根据目标用户和更新要求选择系统包、Flatpak、Snap、AppImage 或其他渠道，说明依赖打包、沙箱权限、签名/校验和更新责任。不要同时支持没有需求依据的全部发行方式。
- **故障与可诊断性。** 对缺失系统库、门户不可用、权限拒绝和桌面服务缺失提供可理解的降级或诊断；不因环境差异静默丢弃用户操作。
- **技术沿用。** 根据已有 Qt、GTK、Electron、Tauri 或其他技术栈判断平台适配点；跨桌面抽象需保留必要的系统差异。

共通框架方法、活动资料选择和交付要求见[客户端框架基础](../hs-dev-framework-client-base/SKILL.md)；此处只保留本平台差异。

## 验证

### 平台执行检查

沿用 Base 的任务类型、授权范围和结果格式，只补充本次涉及的 Linux 差异。

- [ ] **核实工程与环境**：从依赖清单、构建和打包配置确认工具包及版本、CPU 架构、最低系统库、目标包格式和运行时依赖；按需检查桌面入口、显示后端、用户目录与沙箱权限。区分开发宿主、源码启动和实际分发包环境，不凭开发机环境推定支持范围。
- [ ] **选择验证组合**：结合已承诺支持范围、改动触达的机制和已知差异，列出本次需要验证的发行版、桌面环境、X11/Wayland、架构及分发组合。复用仍有效的证据，说明选取理由及未覆盖组合，不默认全组合测试，也不将单一环境结果外推为全部支持范围。
- [ ] **核对机制与边界**：涉及显示后端、门户、桌面服务、沙箱或包依赖时，核对实际工具包、协议和分发渠道对应版本的官方契约，区分标准接口与实现差异。权限、后台运行、数据保留或降级行为未确定时返回当前过程，不擅自扩大权限或增加常驻服务。
- [ ] **执行适用验证**：按下表选择场景，记录操作、预期和实际结果，以及发行版、桌面环境、会话协议、相关版本、架构和包格式。无图形会话、目标设备或渠道环境时标记未验证，不能用无界面测试替代桌面集成结果。
- [ ] **交付**：沿用 Base 的逐项状态和证据格式，明确适用组合、剩余风险及缺失条件；完成当前范围后停止，不自动新增发行渠道、安装系统服务或发布软件包。

### 场景与证据

| 涉及项 | 验证重点 |
|---|---|
| 显示与桌面集成 | 在选定会话下核对实际使用的显示后端、启动和相关窗口/系统交互；按需与 Linux 前端技能共享证据。区分原生 Wayland、X11 与兼容层结果，不以一种后端通过证明另一种后端可用 |
| 门户、桌面服务与权限 | 在实际宿主或沙箱环境检查所用能力的允许、拒绝、取消、服务缺失或不可用结果；核对适配路径与错误传播，不能以开发宿主直连成功证明沙箱内可用 |
| 实例、退出与后台策略 | 按已确认需求检查重复启动、实例通信、退出、进程中断及资源释放；只有涉及后台或自动启动时检查对应注册与清理，不默认要求单实例或常驻 |
| 用户目录与数据 | 核对配置、数据、缓存及运行时文件的实际路径、权限和所有权；涉及升级或路径变更时检查已有数据的读取、迁移及失败结果，不假定清空用户数据可以修复兼容性问题 |
| 分发、安装与更新 | 使用实际目标产物检查依赖解析、桌面入口、安装启动及本次涉及的升级/卸载路径；核对沙箱声明和更新责任。源码启动或构建成功不证明包可安装、可运行或可更新；卸载验证不擅自删除用户数据，签名秘密不进入报告 |

设计任务尚未运行的场景交付验证计划并标记未验证；容器、虚拟显示或其他替代环境的证据须说明局限，不冒充真实目标桌面验证。
