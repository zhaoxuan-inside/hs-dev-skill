# 连续性与恢复

先恢复 task_id、原约束、当前活动、未完成项及其绑定产物，核实内容版本；不要重新分类为完整新项目。恢复后直接回到当前过程，只读当前活动和实际失效依赖。需求变化沿受影响引用扩大范围，不重载所有历史活动；恢复快照与恢复历史不进入模型上下文。工作区中断或漂移时读取[恢复协议](../../share/support/recovery.md)，沿用主入口规定的恢复决策。交接摘要不是任务完成。

## 按场景执行

| 当前情况 | 动作与边界 |
|---|---|
| 普通续做 | 恢复原任务和最小工作集，核验后回到原过程；“继续”不等于授权文件回滚 |
| 需求或约束变化 | 对照原决定记录变化及影响，保留无关成果；评估变化不自动授权实施新增范围 |
| 中断、漂移或明确回退 | 先核验工作区安全、操作归属及恢复条件，再依主入口和恢复协议处理；不绕过冲突或覆盖后续编辑 |

## 执行清单

- [ ] **核实任务身份**：从当前对话和可核验记录恢复 task_id、目标、约束、当前活动、有效决定、绑定产物、源版本、未完成项和阻断。摘要与实际状态不一致时核查来源，无法唯一确定任务或目标时澄清，不新建同义任务或猜测历史决定。
- [ ] **检查工作区条件**：遵循主入口安全协议判断是否可以继续；区分任务未完成与工作区不安全。只读评估不修改内容或确认状态；中断、漂移时先解决安全条件，不消费混合版本或直接开始业务修改。
- [ ] **评估实际影响**：仅在存在变化时区分新增、替换、撤销或澄清，沿实际被消费的需求、契约和引用检查设计、实现、测试及确认。列明保留、受影响及待定项，不全量撤销验收，不把无关源变化当成全部结果失效；受管失效登记沿用统一机制。
- [ ] **检查恢复前提**：只有需要恢复时核实对象、范围、授权、快照完整性、可恢复状态及后续修改冲突。快照过期或缺失时说明不可恢复部分，不直接重建猜测内容；存在未解决冲突时不覆盖。快照正文和恢复历史不装入模型上下文，使用协议提供的状态及核验结果。
- [ ] **验证恢复或续做基线**：实际恢复后核对源内容、配置、任务状态、索引及相关证据一致性；命令成功不等于工作区安全。按当前内容及实际依赖复核旧测试和确认，不冒用旧版本结果；没有执行恢复时不要求额外恢复演练。
- [ ] **回到负责过程**：给出有效目标、当前版本、保留成果、失效项、阻断和下一动作。条件满足后继续原过程的实际未完成工作，不停在交接摘要；尚有冲突时明确缺失信息或外部条件，仅暂停依赖该条件的动作。

## 输出与完成边界

输出最小续做上下文、变化影响或恢复结果，附证据位置及未验证项；简单续做不强制新增交接文档。连续性处理完成不代表原任务完成，不代签确认、不自动发布，也不因上下文恢复重走完整产品发现。

## 上下文边界

只读本任务命中的活动清单，并按目标定位代码与证据；不扩读相邻活动或整阶段资料。安全与范围遵循主入口；涉及写入时按需读取[执行协议](../../share/core/execution.md)，需要验收时读取[验收协议](../../share/core/acceptance.md)。
