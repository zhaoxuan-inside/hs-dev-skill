# E 工程准备

让当前范围具备可实施、可验证的契约和运行条件，不把全项目准备当成单次任务前提。

与用户问答及展示方案时，先遵循[统一表达规范](../../references/questioning.md#面向用户的表达)。

## 进入与活动选择

先核实当前诉求与已有有效成果，仅补当前缺口。按下列活动选择当前对象；不明位置时才查[活动索引](../../references/activities.md)，不加载整个catalog或阶段正文。使用公开命令 `template --activity ID [--output ID]` 只取得当前活动或输出的具体问题、证据与通过标准。模板留空、来源缺失或最坏情况未处理不能作为已完成。

## 必要输入

- 有效行为、质量与架构边界，以及本次交付对象和所需外部保证。
- 实际机器契约、提供消费双方、组件、测试设施、环境和配置来源。

## 本阶段的判断重点

- 逐对象核实类型、空缺、默认、错误、权限、副作用、兼容及数据生命周期，不以工程便利改变业务规则。
- 明确时序、资源、事务与失败窗口；检查超时、重复、部分提交、补偿或向前修复的实际保证。
- 用例预期来自独立业务依据；按需要准备可重复的数据与替身，清楚标识真实接入缺口。
- 配置保持开放且可校验，说明来源优先级、有效值、目标资源和敏感项；不固定制造环境全集。
- 存在跨团队或外部边界时，由提供者、消费者、验证与运维视角独立分析后检查矛盾。

## 最低达成标准

- 当前实现所需契约和决定可判断，代表用例有初态、输入、预期及可用验证入口。
- 环境、数据、配置和适用恢复条件已核实；计划、模拟与实际执行分别记录。

## 执行与交接

完整执行[共同工作循环](../../references/cycle.md)，不另设本阶段的锁、授权或提交流程。查证与阅读遵循[信息规范](../../references/information.md)，主动追问、回答后反例与独立多角色讨论遵循[讨论规范](../../references/questioning.md)。

现行工程契约和验证入口维护在 `hs-dev/project/`；当前切片的准备条件、差异及未验证边界进入 `hs-dev/deliveries/`，实际检查记录由程序保存。

设施可启动不等于业务通过；缺少会推翻实现的保证或必要验证条件时，只阻断相关切片，不编造Mock成功。
