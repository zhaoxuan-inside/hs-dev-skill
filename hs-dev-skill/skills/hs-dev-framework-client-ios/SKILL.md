# iOS 客户端框架

与 [客户端框架基础](../hs-dev-framework-client-base/SKILL.md)配合使用，只补充 iOS 平台的应用架构差异。界面交互由 [iOS 前端特性](../hs-dev-frontend-ios/SKILL.md)和[前端基础](../hs-dev-frontend-base/SKILL.md)负责；服务端结构由后端框架入口负责。

## iOS 框架特性

- **App 与 Scene 生命周期。** 根据项目部署目标定义应用级和窗口/Scene 级状态责任；处理后台挂起、前台恢复、场景连接/断开以及系统回收，不能假设进程常驻。
- **状态和持久化。** 区分短期界面状态、可恢复导航状态和持久业务数据；对中断操作、后台刷新及恢复顺序建立清晰所有权。
- **系统能力适配。** 将通知、后台任务、文件访问、Keychain、分享等系统 API 封装在稳定边界；按最低系统版本处理能力差异和用户撤销授权。
- **并发任务。** 使用项目当前并发模型管理取消、任务优先级和共享状态；后台执行必须符合系统时限，不能把短暂后台机会当作常驻服务。
- **构建与发布。** 管理目标设备、最低 iOS 版本、构建配置、签名和发布渠道。凭证由受控构建环境提供，不提交到仓库。
- **技术沿用。** 依据现有 SwiftUI/UIKit、模块组织和依赖管理方案工作；更换方案需证明现有架构受具体约束阻碍。

共通框架方法、活动资料选择和交付要求见[客户端框架基础](../hs-dev-framework-client-base/SKILL.md)；此处只保留本平台差异。

## 验证

### 平台执行检查

沿用 Base 的任务类型、范围和交付要求，下列检查只补充本次涉及的 iOS 差异，不重复执行共通项。

- [ ] **核实工程**：按需检查 project/workspace、相关 target、部署版本、SDK/工具链、依赖和构建配置；从实际入口确认 SwiftUI/UIKit 或跨平台宿主的生命周期组织。核对相关 Info.plist、entitlements 和能力声明，不输出签名或账号秘密。
- [ ] **选择适用场景**：按实际应用模型区分应用、Scene、任务及持久数据的所有者。仅在目标涉及时纳入多窗口、扩展、后台能力或外部入口；不默认增加 Scene、多窗口、权限或后台模式。必要的恢复、降级或冲突行为未确定时交由当前过程澄清。
- [ ] **核对平台机制**：涉及后台调度、运行时限、授权或数据保护时，核对目标系统和实际 SDK/库版本的官方契约并记录适用条件。按任务持续性、触发来源和系统保证选择机制，不承诺后台任务必定按时执行。并发相关变更核对执行隔离、共享可变状态、取消传播及资源释放，不凭采用某种语言特性证明无竞态。
- [ ] **按场景验证**：采用下表中受影响的场景，记录操作、预期、实际结果、设备/系统版本、构建配置及证据。设计阶段只形成计划时标记未验证；设备或能力不可用时说明缺失条件及影响。
- [ ] **交付平台结果**：沿用 Base 的逐项状态格式，补充真机/模拟器覆盖、未验证能力和剩余风险。完成当前范围后停止；签名、上传和发布依当前过程的授权执行。

### 场景与证据

| 涉及项 | 验证重点 |
|---|---|
| App/Scene 生命周期与恢复 | 分别核对前后台切换、Scene 连接/断开或重建、进程结束后的重新启动；按实际模型检查状态恢复、重复初始化和资源释放。记录进程结束方式及恢复入口，不能以 Scene 重建或调试器终止证明系统回收场景全部通过 |
| 持久数据与中断 | 核对持久化时点、恢复顺序及中断后的可观察结果；涉及数据保护或凭证访问时检查实际可用条件，不依赖进程结束回调必定执行 |
| 后台与并发任务 | 检查适用的过期、取消、重复执行、失败及重试边界；区分调试触发与系统实际调度的证据。检查共享状态隔离和取消后的副作用，不能以任务已注册证明后台执行成功 |
| 系统能力与外部入口 | 按能力覆盖允许、拒绝、撤销或不可用场景；涉及通知、深链接、分享或扩展时检查输入、路由、跨进程数据及权限边界，只验证实际使用的入口 |
| 构建与分发配置 | 核对相关 target、配置、能力声明、签名配置和目标产物的一致性；按需要执行构建或安装验证。模拟器构建不证明设备签名或分发可用，构建成功不证明运行行为正确 |

根据实际平台能力说明模拟器和真机可支持的验证范围；无法复现系统条件时如实标记，不把人工触发结果外推为系统行为保证。
