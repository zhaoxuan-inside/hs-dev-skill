# F 交付规划

使另一个开发者能凭任务入口开始工作、控制范围并判断完成。

与用户问答及展示方案时，先遵循[统一表达规范](../../references/questioning.md#面向用户的表达)。

## 进入与活动选择

先核实当前诉求与已有有效成果，仅补当前缺口。按下列活动选择当前对象；不明位置时才查[活动索引](../../references/activities.md)，不加载整个catalog或阶段正文。使用公开命令 `template --activity ID [--output ID]` 只取得当前活动或输出的具体问题、证据与通过标准。模板留空、来源缺失或最坏情况未处理不能作为已完成。

- `F1` 交付切片规划
- `F2` 任务详细设计
- `F3` 上下文装配
- `F4` 恢复准备

## 必要输入

- 项目目标、有效规则、质量和架构边界；已有切片、依赖及优先级来源。
- 当前工程状态、可用验证条件、授权和需要保护的代码/文档及外部状态。

## 本阶段的判断重点

- 先粗分业务闭环和高返工风险，再细化当前切片；后续范围保留定位，不提前展开全部正文。
- 每个动作明确对象、依据、预期产出、验证、依赖、失败处理与恢复限制，避免仅按文件或技术层拆分。
- 装配必要上下文与实际入口，核对仍有效的认知；后期只问影响当前计划的新差异。
- 跨责任或优先级冲突时由实际产品、实施和运行角色独立分析；不把讨论自动当成并发写入许可。

## 最低达成标准

- 范围与排除项、完成标准、实际对象和首个动作明确，必要输入已就绪或具体受阻。
- 方案含可核验配置、授权、代码与文档锁范围、验证和恢复条件，不能承诺未验证回滚。

## 执行与交接

完整执行[共同工作循环](../../references/cycle.md)，不另设本阶段的锁、授权或提交流程。查证与阅读遵循[信息规范](../../references/information.md)，主动追问、回答后反例与独立多角色讨论遵循[讨论规范](../../references/questioning.md)。

当前范围、任务步骤、必要引用、完成与恢复条件进入 `hs-dev/deliveries/`；项目规则保持单源，索引、计划状态和锁记录由程序管理。

计划不能代替缺失的产品或技术决定，也不能通过另建任务绕过中断、漂移或未解决依赖。
