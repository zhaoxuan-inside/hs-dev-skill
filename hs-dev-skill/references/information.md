# 信息与依据

先按当前问题定位，再取必要正文。文档给开发者可用的规则和理由；索引帮助找到规则，不成为第二份规则。程序生成索引、状态和执行日志，模型不手写这些派生信息。

正文写规则、取舍和有边界的结论；完整日志留在执行证据，用路径和摘要引用，不把日志再次嵌入结果文档。同一事实只维护一个现行正本，来源清单与模板逐项判断可保留在结构化记录，不在每段反复展开。接手优先用控制命令的 `--compact` 查看状态和证据位置，需要原始细节时再读完整响应。

## 三层归属

| 层 | 保存什么 | 不放什么 |
|---|---|---|
| `hs-dev/project/` 项目信息 | 当前产品目标与边界、行为规则、质量标准、架构、工程契约及有效决定入口。 | 每次任务的过程记录、完整对话、重复契约及过期候选方案。 |
| `hs-dev/deliveries/` 交付信息 | 本次范围、真实沟通与追问、决定及原因、采用的方案、实施与验收要求、实际交付物与后续。 | 另一套项目规则、假定已完成的计划或整份执行日志。 |
| `hs-dev/execution/` 执行信息 | 程序生成的定位索引、任务和锁状态、命令日志、真实执行证据及判断记录。 | 由模型伪造的命令输出、手工改写的状态或默认向开发者倾倒的全部历史。 |

一个事实只定义一次：字段在权威契约中维护，决定的理由和被否方案随决定保存，其他材料引用其定位与版本。交付内容可以固定消费的项目依据版本，但不静默成为当前项目权威。已替代资料需标明状态和替代关系，历史不作为默认实施输入。

## 来源要求

| 来源 | 必须核实的内容 |
|---|---|
| 项目文档与实际工程 | 是否为现行内容，适用对象、版本和有效决定；代码证明现状，不能独立证明需求。 |
| 人的回答与反馈 | 原意、具体场景、责任或决定权限、时间及适用范围；转述与直接证据分开。 |
| 已授权私域资料 | 来源位置、访问范围、版本和上下文；未能访问不能冒充已读取，不把敏感内容复制到不必要位置。 |
| 高质量公开来源 | 优先权威原始资料；核实技术版本、发布时间、实际条件和限制，交叉检查有重大影响的争议事实。 |
| 实验与真实运行 | 输入、初态、环境、命令或操作、预期、观察、版本和局限；区分模拟、沙箱与实际目标。 |

外部来源的 `valid_until` 表示最迟重新核验时间，不保证远端在此前不会变化。登记的是已实际采集的快照；联网、私域查询和人与人的沟通由当前 Agent 使用实际可用工具完成，登记程序不会替代这些采集。重大决定或发现新版本线索时提前复核，不能因为快照摘要没变便宣称远端仍然相同。

猜测可以作为待验证假设，不能写成事实或用户确认。来源只能支持其实际覆盖的结论：技术文档不证明业务价值，原型可操作不证明服务可用，测试通过不证明预期充分。

## 检索与阅读

1. 先查程序提供的当前任务和索引，按问题、领域别名、对象 ID、契约、模块或章节定位。
2. 检查候选的适用范围、当前状态与版本，只取命中的规则和必要关联。路径或标题只是定位，不能代替正文。
3. 检查实际引用和覆盖；必要信息缺失时定向补充，不通过全仓扫描或整库粘贴来掩盖缺口。
4. 内容变化后重新定位并复核受影响结论；索引重建不等于需求或验收变化。程序提示源失配时不使用旧结果，也不手改索引伪装新版本。

## 开发者可读的产物

每份材料先回答当前读者问题：结论是什么、适用哪里、必须遵守什么、依据在哪、尚不能确定什么。按独立问题分节，保留稳定定位；长内容按必要语义拆分，不按任意行数切断规则。

模板要求具体字段与可判断标准，但不替项目填写事实。明确未提供、冲突、未实现和未验证，并说明影响及下一动作。输出已写不代表活动目标达成；多份文件也不自动证明信息完整。

接手者无需复读整段会话，应能通过当前任务入口取得目标、范围、有效依据、现状、实际产物、证据、阻断和首个下一动作。需要额外业务判断时仍应向有权者提问，不承诺任何情况下都无需沟通。
