# 前端界面与交互

任何涉及前端界面设计、实现、调试、重构或评审的任务都先加载本 Skill。它提供各端共同的界面设计、实现和验证要求；之后按目标加载 [Web](../hs-dev-frontend-web/SKILL.md)、[Android](../hs-dev-frontend-android/SKILL.md)、[iOS](../hs-dev-frontend-ios/SKILL.md)、[Windows](../hs-dev-frontend-windows/SKILL.md)、[macOS](../hs-dev-frontend-mac/SKILL.md) 或 [Linux](../hs-dev-frontend-linux/SKILL.md) Skill。跨端任务只加载实际涉及的平台。

平台入口只提供端侧交互差异。具体 UI 工具包资料按项目现用技术或正在比较的候选按需读取；不因支持某个平台而加载该平台所有可选框架资料。

应用级框架、路由、渲染和跨页面状态由对应的框架设计 Skill 负责：Web 使用 [前端框架设计](../hs-dev-framework-frontend/SKILL.md)，移动和桌面应用先加载[客户端框架基础](../hs-dev-framework-client-base/SKILL.md)，再按平台加载对应框架特性。

产品规则、角色权限和用户可见行为尚未明确时，由当前过程澄清；界面设计不能自行替产品做决定。

## 工作方法

1. **锁定目标和约束。** 确认用户、使用场景、目标页面或组件、已确认的行为、接口能力、设计系统和支持的设备范围。区分已有约定、实现现状和本次待决定项。具体平台约束由目标端 Skill 补充。
2. **组织信息与操作。** 让主要任务、内容层级、操作入口和结果反馈清晰对应。优先沿用项目的视觉语言和组件；发现不一致时指出影响，不顺手重做整套设计系统。
3. **覆盖适用状态。** 根据功能契约考虑初始、加载、成功、空、输入无效、无权限、失败、提交中、未保存及恢复等状态。只呈现本场景适用的状态，并明确触发条件、用户可执行的下一步和状态结束方式。
4. **保持交互可理解。** 明确触发方式、前置条件、即时反馈、重复操作行为及取消/返回路径。表单校验和错误文案映射到已确认规则；异步操作给出进度或结果，防止重复提交和静默失败。
5. **按局部职责组织组件。** 组件围绕明确的界面职责和变化原因拆分，输入、输出、状态所有权和副作用清晰。先复用已有组件与模式；只有存在稳定复用或独立变化边界时才新增抽象。全局路由、渲染和跨页面状态交给前端框架设计。
6. **实现时遵循仓库约定。** 修改前检查项目使用的组件、样式、类型、格式化、静态检查和测试方式；沿用现有约定。若规范缺失，只为当前改动采用一致、可验证的局部选择，不宣称建立了全局编码标准。
7. **按真实使用方式验证。** 覆盖关键成功和失败路径，检查窄屏/目标设备布局、键盘操作、焦点顺序、语义标签、对比度及错误提示可感知性。根据项目选择组件测试、浏览器/设备验证或端到端测试，记录实际结果和未覆盖边界。

## 执行清单

沿用当前过程的范围、授权和有效上游；上述工作方法按任务选择，不要求每次完整重做设计。

| 任务 | 专业工作重点 |
|---|---|
| 设计 | 将已确认行为落实为界面、状态及交互方案，标明待决定项与验证计划 |
| 实现 | 按已有行为和设计落实组件与代码，核对真实数据契约及适用状态 |
| 调试 | 配合当前过程复现异常，追踪输入、状态、渲染和副作用，以证据定位问题，不凭视觉猜测根因 |
| 重构 | 明确保留的可见行为、组件契约和交互路径，分步验证等价，不顺带改版 |
| 评审 | 对照本次约束报告问题位置、影响和证据，未授权时不实施修复 |

- [ ] **核实基线**：确认本次页面/组件、行为和接口依据，检查实际技术栈、设计系统及相关代码；区分事实、假设和缺失决定。只读任务不修改工程或初始化索引。
- [ ] **选择适用项**：按变更与风险选择上述方法、下方参考及目标端专题；复用有效上游。已有状态不受影响时不重复设计，不为清单增加产品状态、平台、设计令牌或测试设施。不适用说明理由，不跳过已明确要求。
- [ ] **执行当前任务**：按上表落实设计、代码或分析；只修复授权范围内的问题。产品行为缺失时返回当前过程，架构问题交由相应框架技能协同，不用界面猜测补全契约。
- [ ] **验证结果**：按下表选择本次适用检查，记录对象、操作或命令、预期、实际结果和环境；平台专项补充端侧条件，同一证据可以复用。纯设计验证计划与实际执行结果分开。
- [ ] **交付与停止**：逐项给出 `对象／依据／状态／证据／未决项`，状态使用“通过、未通过、不适用、未验证”。说明失败影响、不适用理由及未验证条件。完成当前范围后停止，不自动改版、换栈或发布；简单任务直接回复，不强制新建报告。

### 验证选择与证据

只选择本次受影响的检查，不把每次局部修改升级为全站或全设备审计。

| 涉及项 | 合适的验证与证据边界 |
|---|---|
| 布局与视觉 | 在支持范围内选择代表性尺寸、内容和字体条件检查遮挡、截断、层级及操作可达性；截图证明所示条件下的呈现，不能证明交互或其他尺寸均正确 |
| 交互与状态 | 按已定契约验证相关成功、失败、重复、取消、返回及恢复路径，核对触发、反馈和结束条件；静态审阅不能替代真实交互，组件测试通过不能自动证明系统集成可用 |
| 数据与副作用 | 用适用的契约、组件或集成检查核对字段、错误映射、状态同步及提交结果；注明夹具、Mock 与真实服务边界，不以模拟成功宣称真实接入通过 |
| 可访问性 | 按下方共通检查及平台专项选择人工、辅助技术和自动检查；自动扫描结果不能覆盖全部语义、焦点与操作行为 |
| 代码与构建 | 执行项目已有且与改动相关的类型、静态、构建或测试检查；命令成功只证明对应检查，不证明视觉和交互全部正确 |

没有浏览器、设备、服务或辅助技术环境时标记未验证，说明局限及后续验证方式。已有证据仅在对象、条件和相关内容仍适用时复用；专业自检不代替人工验收。

### 共通可访问性检查

按本次控件和交互选择，平台专项补充实际工具及系统行为：

- **名称与语义**：控件名称、角色、状态和内容关系可被辅助技术理解，非文本内容有合适替代；装饰内容不干扰阅读。
- **操作与焦点**：目标支持的键盘、触控及辅助输入能完成核心任务；焦点顺序、可见性、弹层进入/退出与返回位置合理，不产生无法退出的路径。
- **反馈与错误**：字段、说明、错误及动态状态关联清楚，反馈可感知，不只依赖颜色、位置或动画；修复与下一步由已定契约决定。
- **可读与适配**：按目标要求检查对比度、文字放大、内容重排和操作目标可用性；涉及运动或时限时核对对应替代或控制要求，不为无关任务增加机制。

项目已指定可访问性标准、等级或平台规范时核对适用版本及条目并关联证据；未指定时只报告实际检查范围，不宣称全面合规。发现产品层面的取舍由当前过程处理。

## 前端代码约束

本节在任务包含前端代码编写或修改时生效；纯设计和评估任务只需把相关要求写入方案。

- **沿用项目约定。** 先看仓库指令、附近代码、组件库、设计令牌及格式化/检查命令。具体语言和框架写法由项目已有规则决定；显式项目规范优先于局部习惯。不要在 Skill 中推定项目使用某个框架或目录结构。
- **组件边界清楚。** 组件对外输入、事件和状态职责明确。显示组件不过度承载业务规则；副作用和数据请求遵循项目既有边界。避免为一次性使用场景增加通用层，也避免多个组件各自保存同一事实的副本。
- **呈现真实契约。** 界面读取和提交的数据遵循已确定的 API 契约。加载、空、错误、权限不足和提交中状态按实际行为呈现；测试夹具不进入正式用户路径，不吞掉服务端错误。
- **样式与布局一致。** 优先使用既有设计令牌、排版尺度、间距、组件和断点；布局在支持的屏幕尺寸下保持内容、操作和反馈可用。避免在多个组件复制同一套样式常量。
- **交互可访问。** 使用适合控件含义的语义元素，支持键盘和可见焦点；表单字段、校验错误、异步状态和动态反馈能被辅助技术识别。非文本内容提供合适替代，颜色不是唯一的信息载体。
- **验证与改动匹配。** 运行本次改动适用的类型、静态、组件或界面检查；交互风险较高时验证实际浏览器或设备行为。失败和未执行项如实记录，由当前过程管理验收证据。
