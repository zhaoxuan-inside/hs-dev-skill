# Windows 客户端框架

与 [客户端框架基础](../hs-dev-framework-client-base/SKILL.md)配合使用，只补充 Windows 平台的应用架构差异。窗口内容与输入体验由 [Windows 前端特性](../hs-dev-frontend-windows/SKILL.md)和[前端基础](../hs-dev-frontend-base/SKILL.md)负责；服务端结构由后端框架入口负责。

## Windows 框架特性

- **进程和窗口模型。** 明确单实例/多实例策略、窗口所有权、窗口关闭与应用退出关系；多窗口或后台常驻只在产品和运行要求支持时引入。
- **系统集成边界。** 文件选择、剪贴板、通知、协议链接、托盘和系统服务通过可替换的适配层接入；处理系统能力不可用、用户取消和权限受限。
- **运行环境。** 明确最低 Windows 版本、CPU 架构、安装范围、用户数据位置和升级策略；多显示器、休眠恢复及用户切换的影响按支持范围验证。
- **打包与更新。** 根据目标渠道选择安装、签名和更新机制；升级应保护用户数据并能识别失败，不把开发环境配置带入正式包。
- **技术沿用。** 使用仓库已采用的 WinUI、WPF、.NET、Electron 或其他框架约定。跨平台桌面壳的共用与平台特化边界需有实际维护收益支撑。

共通框架方法、活动资料选择和交付要求见[客户端框架基础](../hs-dev-framework-client-base/SKILL.md)；此处只保留本平台差异。

## 验证

### 平台执行检查

沿用 Base 的任务类型、授权范围和结果格式，只补充本次涉及的 Windows 差异。

- [ ] **核实工程基线**：从工程、依赖、构建及安装配置确认实际框架与工具链版本、目标 Windows 版本、CPU 架构、运行时依赖、启动入口和应用清单；按需确认打包/非打包模型、应用身份、安装范围与更新渠道。区分开发启动和最终部署环境，不以技术名称推定部署能力。
- [ ] **选择适用项**：依据本次变更和承诺支持范围，选择实例、窗口、系统集成、恢复、数据或分发场景。复用有效证据，说明未覆盖组合；不为清单额外引入多窗口、托盘、常驻、系统服务或安装渠道。
- [ ] **核对机制条件**：涉及系统 API、应用身份、权限、线程调度或部署时，核对实际框架、运行时和目标系统的官方契约。明确相关窗口/UI 线程、后台任务和资源的责任边界；只有所用接口要求时检查相应线程或互操作条件，不把某一框架模型套用于所有项目。权限不足时按既定行为处理，不默认请求管理员权限。
- [ ] **执行场景验证**：从下表选取受影响场景，记录操作、预期和实际结果、Windows 版本、架构、运行时、用户权限、包格式及安装范围。纯设计任务交付验证计划并标记未验证；没有目标环境时说明缺失条件和影响。
- [ ] **交付与停止**：沿用 Base 的逐项状态和证据格式，列出未验证的平台行为及剩余风险。完成当前范围后停止，不自动注册系统服务、扩大安装权限、上传签名材料或发布安装包。

### 场景与证据

| 涉及项 | 验证重点 |
|---|---|
| 实例、窗口与退出 | 按已确认策略检查重复启动、参数转交、窗口所有权、关闭和进程退出；核对后台任务、订阅及资源释放。按需与 Windows 前端技能共享窗口验证证据，不默认单实例或关闭窗口即退出 |
| 系统能力与入口 | 对实际使用的通知、协议链接、文件或其他系统入口检查输入、取消、权限受限及能力不可用结果；核对应用身份与注册条件，避免以开发环境已有注册证明安装后可用 |
| 运行恢复与会话 | 仅在目标涉及时检查休眠/恢复、用户会话变化和窗口重建后的资源及状态；涉及多显示器的界面行为交由前端专项协同。不同会话或恢复场景分别取证，不互相替代 |
| 数据与配置 | 核对用户级或机器级目录、访问权限和所有权，避免依赖安装目录可写；涉及升级时检查旧数据读取、迁移、中断和失败结果，不以删除用户数据替代修复 |
| 构建、安装与更新 | 检查实际目标架构、依赖、安装范围和产物；按需要验证安装启动、升级、卸载及失败路径。开发启动或构建成功不证明分发包可运行，管理员环境结果不证明普通用户可用，一种架构结果不代表其他架构；卸载不擅自清除用户数据 |

签名、安装及更新机制按实际渠道核验，凭据不进入报告。替代环境的验证须说明局限，不把静态审阅、模拟结果或未执行的计划标记为真实环境通过。
