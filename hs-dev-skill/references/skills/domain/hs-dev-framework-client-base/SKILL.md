# 客户端框架设计基础

任何移动端或桌面客户端框架设计、实现、调试、重构或评审任务都加载本 Skill，再按目标加载 [Android](../hs-dev-framework-client-android/SKILL.md)、[iOS](../hs-dev-framework-client-ios/SKILL.md)、[Windows](../hs-dev-framework-client-windows/SKILL.md) 或 [Linux](../hs-dev-framework-client-linux/SKILL.md) 平台入口。跨平台任务只加载实际目标平台。macOS 客户端目前使用本通用入口；涉及界面行为时再加载[macOS 前端特性](../hs-dev-frontend-mac/SKILL.md)。

平台入口只提供操作系统差异。具体工具包资料按项目现用技术或正在比较的候选按需读取；例如项目使用 Compose 时不加载 SwiftUI、Qt 等其他技术资料。没有独立工具包决策时沿用项目现有栈，不加载候选框架资料。

本 Skill 中的技术名称只是用于说明决策维度的例子，不是完整目录，也不承诺代表最新或推荐方案。若任务需要新选型或迁移，按目标平台和团队约束确定候选，并核对候选技术的官方平台支持、最低系统版本、发布状态及维护策略；在决策记录中标明核验日期和官方来源。不要仅凭本地文档中的示例判断技术仍受支持。

本 Skill 关注应用壳、运行边界、生命周期、状态持久化和设备/操作系统能力，不负责逐页面的视觉与交互细节。Web 应用架构由 [Web 前端框架设计](../hs-dev-framework-frontend/SKILL.md)负责；各端界面行为由 [前端基础](../hs-dev-frontend-base/SKILL.md)及相应端侧 Skill 负责；服务端内部结构由[后端框架设计](../hs-dev-framework-backend/SKILL.md)负责。

## 设计方法

1. 确认目标平台、最低系统版本、设备能力、分发方式、现有技术栈、联网与离线要求；区分平台硬约束、产品需求和偏好。
2. 根据目标平台覆盖、原生能力、性能、团队经验、发布节奏和维护成本比较原生或跨平台方案。若跨端框架选型是本次任务的一部分，按需读取[跨端框架选型参考](references/cross-platform-selection.md)；Flutter 是可评估的跨端候选之一，不因本 Skill 的平台分层而排除。以现有技术不能满足明确约束为升级/迁移理由，不因流行度改换技术栈。
3. 设计启动、前后台切换、挂起/恢复、导航和退出等应用生命周期；确定页面状态、进程级状态和持久状态的所有者与恢复规则。
4. 对本地存储、缓存、离线操作和服务端同步，定义数据新旧、冲突处理、重试及凭证生命周期；说明断网、进程终止和升级后的可观察结果。
5. 将系统能力置于清晰的适配边界，明确授权拒绝和能力不可用时的处理方式；平台差异集中表达，避免业务规则散落在平台条件分支中。
6. 安装、签名、升级、深链接、系统集成和崩溃恢复只在目标交付或质量要求涉及它们时纳入设计。

## 按任务执行

沿用当前过程的目标、授权和有效上游，不因加载本 Skill 重做架构或选型。只读任务仅分析，不修改工程或初始化索引。

| 当前任务 | 本 Skill 的工作 |
|---|---|
| 设计 | 依据上述方法形成本次需要的边界、取舍及验证计划；关键未知按范围验证 |
| 实现 | 将已确定的契约落实到相关模块、生命周期或平台适配，检查实际代码与决定一致；不重新决定产品行为 |
| 调试 | 配合当前调试过程追踪启动、状态、存储、同步或平台调用链，核对异常证据与相关边界，不把推测当根因 |
| 重构 | 明确保留的可观察行为和影响范围，分步检查接口、状态恢复及平台行为等价，不借重构迁移技术栈 |
| 评审 | 对照本次约束核对设计或代码，输出问题位置、影响与证据；未授权时不顺带修改 |

### 执行清单

- [ ] **核实基线**：定位实际目标平台、工具链与依赖版本、启动入口、模块和配置，以及本次相关的产品契约、质量要求和已有决定。区分事实、假设和缺失输入；从工程可确定的信息不重复询问。
- [ ] **选择适用项**：按本次任务选择下方活动条目及平台专项；复用有效结果，不把引用清单整套变成必做项。文档数量、环境划分和测试设施依实际约束确定；不适用项说明理由，不跳过已明确要求。
- [ ] **处理专业问题**：按任务类型执行，确定状态与资源所有者、依赖和失败边界。涉及平台或工具包机制时核对实际版本的官方契约或工程证据；必要产品决定缺失时返回当前过程，仅暂停依赖该决定的动作。
- [ ] **协调专项与验证**：共通项由本入口指导，操作系统差异由目标平台入口补充，同一证据可复用。跨端共享层与各端适配层分别核对；只执行本次相关的验证，不默认要求完整设备矩阵。
- [ ] **交付与停止**：给出已选检查项的结果、证据和剩余风险，完成当前范围后停止；不自动扩展平台、安装工具包、迁移数据或发布应用。

### 验证选择

根据变更或设计风险选择适用项。纯设计任务可交付静态证据和验证计划；计划与未执行的检查不得标记为运行通过。

| 涉及项 | 核验方式与证据 |
|---|---|
| 启动、生命周期和状态所有权 | 对照入口、调用链及状态转换检查初始化、订阅和资源释放；按平台专项区分界面重建、挂起恢复与进程终止，验证本次要求的恢复行为 |
| 本地数据、缓存与升级 | 核对持久边界、数据版本及失效策略；适用时用代表性旧数据检查升级、读取失败和中断后的结果，不默认清空用户数据 |
| 离线操作与同步 | 按已确认语义检查断网、重连、重复提交、冲突和部分失败；区分客户端可保证的行为、服务端保证及模拟范围，不能以 Mock 通过证明真实同步成功 |
| 平台适配与共享模块 | 核对依赖方向、接口和能力不可用时的结果；适用时执行边界测试或目标平台集成验证，共享层通过不能代替各端适配验证 |
| 构建、配置与安装升级 | 检查相关目标和变体的实际构建、配置加载或安装升级路径；按任务需要执行，不以构建成功代替运行行为验证 |

记录验证对象、方法、条件和实际结果；设备、服务或工具不可用时明确未验证项及影响。macOS 当前没有独立框架专项入口：涉及其生命周期、应用模型、打包或系统集成机制时，按项目实际工具包和系统版本核对官方资料并安排专项验证，不能用 macOS 界面检查代替框架验证。

## 产出与边界

每个已选检查项记录 `对象／约束与决定／状态／证据／未决项`，状态使用“通过、未通过、不适用、未验证”。不适用说明理由，未验证说明缺失条件及后续方式；未通过说明影响和处理建议。简单任务直接回复即可，不强制新增文档。专业自检不替代当前过程的人工确认。

交付本次需要的平台范围、框架取舍、模块职责、生命周期或本地数据策略、平台适配边界和验证依据。将设备端可保证的行为与服务端契约分开说明；跨端规则以已确认契约为准。平台相关的实现和验证要求由对应平台 Skill 补充。产品行为未明确时返回当前过程澄清，不自行定义交互规则。当前过程负责任务范围、执行和确认；本 Skill 不要求加载整套 C、D 或 E 阶段资料。
