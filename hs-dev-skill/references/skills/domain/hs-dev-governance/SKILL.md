# 工程与文档治理

负责术语、产物登记、覆盖、索引及必要工程约束；不自动启用无关基础设施。

沿用当前过程已选定的活动、目标对象及上下文；专业职责不增加活动范围。不读取 workflow 总目录或整阶段资料。只有发现具体专业缺口时，向当前过程说明缺失的决定或证据，由该过程选择对应活动；已加载的共同约束不重复读取。

## 执行清单

按本次任务执行以下步骤；专项检查仅选择命中条件的行，不把局部维护扩大为全项目审计。

- [ ] **确定边界**：引用当前活动、目标文件或产物、预期结果、读写权限及已有工程约束。沿用有效的上游决定，不另建同义任务或重做产品设计。只读任务不初始化、修复或刷新索引。
- [ ] **选择适用项**：依据下表选取本次涉及的检查，并定位源文档、活动清单和既有记录。配置不存在不等于治理项全部启用；只有缺失信息会影响本次结果或修改范围时，才交由当前过程澄清。
- [ ] **核对与处理**：先核对实际源内容，再维护授权范围内的记录；索引和登记不能替代源内容。发现范围外问题记录位置及影响，不顺带修复；必要上游缺失或决定冲突时，报告当前过程，暂停依赖该决定的动作。
- [ ] **验证**：对修改后的实际内容执行适用检查，记录对象、方法、结果及证据位置。无法执行的检查标记“未验证”并说明原因，不能把文件存在、命令成功或配置齐全等同于通过。
- [ ] **交付**：汇报已选检查项的状态、变更及未决问题；说明未覆盖的范围。授权范围内适用项已有验证结论、未决项已明确交接后结束，不自动扩展到下一活动；人工确认由统一模块按任务模式处理。

## 专项检查选择

下列路径相对于本文件。活动已有清单时复用其标准，本表只补充治理视角，不另设阶段门禁。

| 命中条件 | 检查内容与完成依据 | 按需读取 |
|---|---|---|
| 本次新增或改变术语、名称、标识 | 对照已有词典及源文档核对含义、命名和引用；同名异义或同义多名有明确解释，不自行改变产品含义 | 当前对象的词典及契约 |
| 本次新增、修改或移交产物 | 登记能定位实际产物及适用版本；引用、归属和依赖与实物一致，无失效链接或仅登记而无内容的交付 | 当前活动契约；涉及确认有效性时读[验收协议](../../../core/acceptance.md) |
| 当前活动要求覆盖核验，或本次改变追踪关系 | 沿本次受影响的需求、设计、任务、实现和验证关系核对；遗漏、孤立项及不适用项有解释，不虚构覆盖证据 | [H1 覆盖清单](../../../workflow/h_delivery_feedback/h1_coverage_review/checklist.md)，只取适用条目 |
| 本次涉及索引、导航或缓存一致性 | 核对源版本与定位结果，检查受影响引用可达；源内容优先。发现索引损坏按显式修复流程处理，不在读取时自动重建 | [索引协议](../../../indexing/protocol.md)；写入时读[执行协议](../../../core/execution.md) |
| 当前任务涉及版本、发布或工程规则 | 依照已有版本约定、发布范围和已启用的配置检查实际产物；仅对本次涉及的机密、依赖、安全等规则取证。不默认安装工具或启用 CI/CD、遥测等设施 | 项目现有规则；涉及写入和发布时读[执行协议](../../../core/execution.md) |

## 结果要求

每个已选检查项给出：`对象／依据／状态／证据／问题与下一步`。状态使用“通过、未通过、不适用、未验证”；不适用须说明理由，未通过须说明影响，未验证须说明缺失条件。简单任务可直接在回复中呈现，不强制新建报告文件。

治理检查通过只表示本次适用规则得到验证，不替代产品验收，不代签人工确认，也不自动授权 Git push、发布或修改其他 Agent 配置。
