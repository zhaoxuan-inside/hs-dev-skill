# 存量调查

先明确要重建的对象及代码范围，从实际入口追到数据或外部出口。只读取该对象对应的清单；逐个对象扩展，不预读全项目资料。观察事实、推断和未知分别记录，代码现状不自动成为已确认需求。仅解释现有项目时切换 exploration。

## 执行清单

- [ ] **确定调查基线**：明确要重建的对象、代码范围、源版本、相关环境、预期产物和授权。优先复用现有有效资料；重建知识不等于授权修改业务代码、访问生产数据或运行有副作用的实验。只读分析不创建任务、文档或索引，按主入口选择 exploration。
- [ ] **逐对象追踪**：沿实际入口、调用、状态、数据及外部出口建立关系，按需要加载领域技能解释专业含义；记录文件、符号或配置位置。只沿具体证据缺口扩展，搜索未命中或单个入口未触达不能证明功能不存在，未访问范围明确标记。
- [ ] **交叉核验**：对照相关代码、配置、迁移、测试及已有文档，区分静态声明、可达实现和实际运行证据。冲突逐项记录来源、版本和影响，不擅自认定哪方代表正确需求；必要运行检查由 testing 协同，在授权环境执行，缺失条件标记未验证。
- [ ] **形成现状知识**：按当前对象使用下表清单组织已观察的行为、结构或契约。设计清单用于检查观察维度及未知，不用于补造不存在的字段、规则、恢复机制或接口；推断说明依据，未知说明缺失证据。代码现状不自动升级为产品决定，改进建议与现状分开。
- [ ] **维护可追溯产物**：在授权范围内更新已有文档或形成必要记录，关联对象、源版本、结论、证据位置、推断及未知；遵循受管写入协议。需要登记或索引时由治理能力按适用规则处理，不为调查默认建立整套文档、重复索引或改写 Agent 配置。索引只是定位派生物，不证明知识正确。
- [ ] **核实并交接**：展示实际调查范围、主要结论、冲突、未验证项和下一动作，按当前模式处理确认；需要开发者核实的业务含义或边界不能由模型代签。范围内对象已有可追溯结论、未知有明确交接后结束，不将局部调查说成全项目知识完整；后续修复或设计交回负责过程，不顺带实施。

## 输出要求

每个对象记录 `现状结论／源版本及位置／证据类型／推断与未知／核实状态`。区分文档完整、事实得到证实和人工确认三个结果；授权产物可保留明确未知，不以编造内容补齐清单。简单对象可更新现有记录，不强制另建报告；相关源变化后仅复核受影响结论，不全量重建无关知识。
