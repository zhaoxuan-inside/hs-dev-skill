# 结构重构

起步读取目标模块、直接调用方、相关契约和现有测试，确定保持的行为。只沿实际变化的边界扩展；不为核验 A/B 而加载完整需求。逐步调整并比较前后行为；意外行为变化作为回归处理，既有缺陷交由 debugging，只有明确希望改变产品行为时才进入需求变化过程。

## 执行清单

- [ ] **确定结构目标**：说明当前结构问题、影响对象、授权范围及预期改善，如职责集中、依赖简化或重复事实消除。以实际代码和变化原因支持判断，不为模式、抽象或代码行数本身重构。只读评审不修改工程。
- [ ] **建立行为基线**：核实有效契约及当前实现，按适用范围列出输入输出、错误、状态转换、副作用、持久数据、公开接口、兼容性和重要性能/资源约束。区分必须保持的行为与已知缺陷；现状与要求冲突时交回负责过程，不自行认定偶然行为必须保留或可以删除。
- [ ] **选择保护与方案**：按实际边界调用领域技能，与 testing 复用或补充有意义的特征、契约及集成检查，说明基线版本和覆盖局限。内部方法可通过调用链保护，不要求逐方法测试；测试不足时按风险补足，不能直接把实现细节复制成断言。结构决定缺失时只补对应设计，不重做全架构。
- [ ] **小步调整**：按主入口受管写入协议执行可验证的增量，必要时同步内部接口和调用方，保持有效公共契约与兼容要求。不借重构添加功能、修改业务语义、迁移技术栈或删除有效兼容路径。每步检查当前影响，验证失败先定位本步原因，不叠加未经验证的大量调整。
- [ ] **比较与回归**：对照同一组行为场景核验前后结果及必要集成；内部结构可变化，公共结果、副作用和已定质量约束仍须满足。意外回归在当前范围修复，独立既有缺陷单独交接；需要恢复时核验操作归属及后续冲突，不覆盖其他修改，中断或漂移交由 continuity。
- [ ] **交付与结束**：以代码位置和实际检查说明结构目标的改善，关联行为保护结果、源版本、真实/模拟边界及未验证项。目标已达成且相关检查无未解释失败后按当前模式处理完成；仅部分验证时限定结论，不以编译通过或代码变少证明等价，不自动发布。

## 输出要求

给出结构问题与改动、保持的行为边界、验证证据和剩余风险；复用 testing 的通过、未通过、不适用及未验证状态。简单任务直接回复，不强制新增报告；专业自检不代签人工确认，范围外问题保留位置及影响，不顺带扩大修复。

## 上下文边界

遵循[主入口](../../../../../SKILL.md)的安全与读取协议；已在上下文中的共同约束不重复加载。活动清单只定义标准，任务代码和产物另按对象定位。扩读前说明缺失的决定或证据及其影响；没有具体缺口时不读取相邻活动、阶段目录或整个 workflow。
