# 缺陷修复

起步只读复现步骤、错误证据、受影响调用链及其预期契约。提出可验证假设，按证据追踪根因；不要以 H1 为由加载全项目资料。纯实现错误直接修复并回归，不重做设计；只有证据指向设计或需求缺口时，才切换相应过程并选择具体活动。

## 执行清单

- [ ] **建立复现基线**：核实预期契约与实际结果，记录源版本、环境、输入、步骤、频率及影响。优先复用已有错误和最小复现，区分既有失败与本次异常；无法复现时说明已检查条件和缺失信息，不宣称已定位。只要求分析时不实施修改。
- [ ] **提出并检验假设**：从受影响入口、调用链、状态和依赖提出有依据的候选原因，优先选择能区分候选的最小检查；记录观察、支持或排除依据，再决定是否扩读。不要通过无目的改参数、扩大日志或反复重跑代替诊断；取证不输出凭据或不必要的用户数据。
- [ ] **确认因果链**：解释原因怎样导致症状、为何符合触发条件，并区分已证实结论与推测。暂时绕过、重启或增加兜底属于缓解，不自动证明根因；证据不足时报告剩余假设及下一检查，不编造确定性。设计或产品决定缺失时切换负责过程，不自行补契约。
- [ ] **实施最小修复**：仅在当前授权内修改已定位问题及必要关联项，遵循有效需求和兼容约束，不借机改版、重构或换栈。引用 G1 时不得将“旧格式兼容”笼统解释为删除项目明确要求的兼容行为；存在标准冲突时交回当前过程裁决。涉及受管写入遵循主入口执行协议。
- [ ] **验证与回归**：与 testing 协作选取能区分缺陷前后行为的检查；条件允许时确认修复前因目标行为失败、修复后通过。按受影响调用链扩展必要回归，区分环境故障、既有失败和非确定性问题；不得通过删除断言、放宽预期或一次重跑成功掩盖未解释失败。
- [ ] **交付并结束**：报告复现条件、根因及依据、实际改动、源版本、验证结果和剩余风险。确认目标异常已被适用证据覆盖、相关回归无未解释失败后，按当前模式处理完成；仅缓解、未验证或无法复现时限定结论，交接下一动作，不宣称彻底修复。完成当前范围后停止，不自动发布或扩大审计。

## 结果要求

区分“已证实根因、候选原因、临时缓解、已修复且验证、待验证”等结论；证据包含命令或操作、环境、预期与实际结果及位置。复用 testing 的逐项状态和证据，不另建竞争性测试记录；简单任务直接回复，不强制新增报告。人工确认由当前过程和统一模块处理，不以模型诊断代签。
