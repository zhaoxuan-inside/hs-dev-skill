# 交付规划

从已明确的需求分母、设计引用和本次交付范围开始。切片已确定时不重做 F1；只为当前切片装配上下文，后续切片保留定位引用。发现设计缺口时切换对应设计活动，不读取整套设计资料。

## 执行清单

- [ ] **核实规划基线**：确认本次交付范围、完整需求分母、有效设计、约束、现有任务及依赖。区分已决定、建议和未决项；局部调整只重算受影响部分，不重排无关计划。必要产品或设计决定缺失时返回负责过程，不靠规划补业务规则。
- [ ] **划分结果与依赖**：需要切片时围绕可验证的业务结果拆分，识别输入依赖、集成点、风险和先后顺序；避免只按文件或技术层拆分却无法演练结果。按授权范围安排优先级及分期，不隐含延期、删除需求或擅自承诺工期。
- [ ] **形成最小任务契约**：列出目标、有效输入引用、影响对象、执行检查、验证方式、依赖、完成条件及恢复要求。对象定位到当前需要的粒度，不臆造尚未确定的方法；简单内部方法可由调用链覆盖，不要求每个方法独立任务或测试。领域技能协助核对专业细节，testing 协助判断验证可行性。
- [ ] **装配当前上下文**：只为选中任务装配必要目标、约束、契约及对象，保留源版本、摘要和定位；后续任务仅保留引用。必要依赖缺失或预算不足时报告具体缺口，不裁掉约束或递归加载全部历史；沿用主入口上下文协议核验完整性。
- [ ] **检查执行与恢复条件**：区分计划依赖、任务登记限制与工作区安全。可以分析独立任务的计划，不因此绕过 F2.3 或运行时的新任务门禁；门禁拒绝时说明原因并交由 continuity/用户处理，不伪造前序完成。规划只说明恢复范围、冲突保护和验证要求；实际快照、日志及清理由执行协议落实，不因只读规划自动初始化或改动恢复记录。
- [ ] **核验并转交**：对账本次范围与任务映射，检查无遗漏或未解释孤立项、依赖无循环、输入有效且验证可判断。关键设计缺口未解决时标记阻断；非阻断未决项说明条件及下一动作。按当前模式处理确认后，依已有授权转入实施；只要求计划时止于计划，不自动写业务代码或发布。

## 输出与就绪标准

交付当前任务或切片清单、需求映射、依赖顺序、必要上下文及证据引用、就绪状态和未决项。复用已有任务记录，简单计划可直接回复，不强制创建新的文档层级。任务可执行、关键依赖满足、验证及恢复要求清楚后才称就绪；计划完整不代表实现、测试或人工验收已经完成。

## 上下文边界

遵循[主入口](../../../../../SKILL.md)的安全与读取协议；已在上下文中的共同约束不重复加载。活动清单只定义标准，任务代码和产物另按对象定位。扩读前说明缺失的决定或证据及其影响；没有具体缺口时不读取相邻活动、阶段目录或整个 workflow。
