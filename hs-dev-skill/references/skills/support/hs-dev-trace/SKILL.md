# 可选摘要追踪

按配置记录本项目摘要事件，best effort且默认关闭。遵守[主入口](../../../../../SKILL.md)及[专属协议](../../../support/trace.md)，不改变业务验收权限。

## 执行清单

- [ ] **明确目的与项目**：确定需要解释的运行、路由或操作问题及工程根；普通任务不为完整性自动开启 trace。沿用已有开关授权，不因追踪需要创建业务任务或申请业务修改 UUID。
- [ ] **核实开关**：检查实际解析配置及 banner/JSON meta，区分默认关闭、`trace.enabled` 持久配置和全局 `--trace` 对当前调用的临时开启。临时参数不等于已保存配置；更改持久设置需在当前授权范围内，沿用配置机制，不自行编辑其他 Agent 配置。trace 不改变 mute/activity/stage 确认责任。
- [ ] **选择有界查询**：优先按已知 run/task/operation/activity、事件或结果过滤，再加时间范围和数量限制；使用下述现有命令，不默认读取整个日志或加载业务正文。已关闭时仍可查询已有记录，不为查询自动开启追踪或重放业务。
- [ ] **解释结果与局限**：将事件与实际操作标识及时间关联，区分已观察事件与推断。空结果可能来自未开启、过滤未命中、容量/时间淘汰或记录丢弃，不能证明业务未发生。数量上限不代表总量，返回顺序不保证全局时间倒序；需要比较时只对已取得样本排序并说明覆盖范围。
- [ ] **处理记录或查询失败**：写冲突、容量限制及记录失败按协议允许丢弃，不阻断或重试业务动作。查询出错时保留错误并报告摘要不可用，不把它当业务失败，也不手工删锁、改日志或扩大读取范围来伪造完整记录。丢弃计数是进程内计数及部分事件携带的观察值，不能当作跨进程完整历史统计。
- [ ] **交付并停止**：给出查询条件、样本范围、关键摘要、未知及下一动作；trace 只是诊断线索，结论需要时由实际代码、状态或测试证据核验。完成后不自动持久开启、清理或导出追踪；不以追踪代替恢复日志、验收证据或人工确认。

## 查询方式

通过 `python <安装根>/hs-dev-skill/scripts/hs_dev.py --root <工程根> trace-query` 查询；按需要加 `--run-id`、`--task-id`、`--operation-id`、`--activity-id`、`--event`、`--outcome`、`--since`、`--until` 及 `--limit`。具体参数以当前 CLI 帮助为准，数量限制为 1～100；时间建议使用带时区的 ISO 8601，起始不得晚于结束。

首次按最具体的已知标识查询；未命中时核实项目、标识和时间条件，只为明确缺口逐步放宽，不直接扫全项目历史。操作标识以实际事件为准，不能将 task_id、run_id 与 operation_id 混用。查询不会保证返回全部历史，轮换及淘汰后的事件不承诺可恢复。

## 数据与结果边界

仅使用协议白名单中的必要摘要，不向事件字段塞入凭据、完整对话、代码、文档正文或不必要的用户信息；字段白名单和字符串截断不等于内容已经脱敏。日志不进入业务索引、快照或默认模型上下文，诊断仅提供所需过滤摘要，不生成完整日志副本。

输出记录实际开关/配置来源、查询范围、观察结果、缺失条件及结论置信边界。未查询或查询失败不宣称追踪正常，未观察到事件不等于功能异常；简单任务直接回复，不强制新增报告。
