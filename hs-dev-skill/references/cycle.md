# 共同工作循环

所有阶段使用同一循环，但只展开当前活动需要的工作。目录和模板给最低交付要求；领域问题、实际约束及风险决定细化程度。普通只读解释在证据足够后返回结论，不初始化、写文档或取得写锁。

| 环节 | 开发者需要做的事 | 进入下一环节的条件 |
|---|---|---|
| 1. 查证来源 | 从当前文档和实际工程开始，必要时询问人、访问已授权私域资料或高质量公开来源。检查内容版本、适用环境、时间及来源能支持的结论。 | 事实、假设、建议与未知已分开；关键证据缺口可定位。 |
| 2. 建立理解 | 用真实事件、角色任务、对象生命周期及反例解释问题。按需要独立组织相关角色讨论；提问后检查回答引起的新冲突。 | 当前目标和关键语义可判断；需要负责人决定的事项有明确处置。 |
| 3. 明确最低标准 | 选择活动和产出模板，固定当前范围、必须保持的规则、适用质量标准和可观察结果。 | 能区分做到、没做到、不适用和未验证；没有用新增文档替代实际结果。 |
| 4. 制定方案 | 根据有效约束选择或沿用方案，安排小步动作、验证方法、失败处理和恢复条件。必要时用最小实验区分关键假设。 | 执行者知道改什么、如何验证、失败后怎么办；影响方案的未知已解决或保持阻断。 |
| 5. 配置与授权 | 核实实际环境、工具入口、配置来源及外部副作用。区分硬约束、可配置选项、建议默认值和秘密。按用户当前及既有授权判断可执行范围。 | 必要配置可核验；允许的动作与需额外决定的动作分开，不反复询问已授权内容。 |
| 6. 锁定与复核 | 通过程序取得覆盖相关代码和文档的锁，核实锁归属、源版本、已有修改和前置产物。发现变化重新评估影响。 | 当前基线与计划、依据和实际写入范围一致；未取得有效锁不写入。 |
| 7. 小步执行同步 | 每步只改当前目标需要的对象，同步受影响的说明、契约和验证。意外行为变化先解释原因；规则确需变化时返回负责阶段。 | 实际修改、关联资料及剩余问题可追踪，没有用实现方便替代业务决定。 |
| 8. 验证与一致性提交 | 实际运行适用检查，核对结果、副作用和版本；按原始规则评审实现与用例。修复后复验受影响部分，核对资料与代码后通过程序提交一致结果。 | 无未解释的阻断，证据对应当前内容；计划、模拟、跳过和真实运行没有混写。 |
| 9. 最后解锁 | 核对一致性提交结果、交付状态和未完成项，再通过程序释放锁并交接下一动作。 | 源、文档和状态可安全消费；未知或中断状态不得伪装完成。 |

## 不把循环变成重复劳动

每轮结束后对照用户主目标检查剩余工作，沿实际依赖继续下一活动。`submit` 只提交当前活动，不判定主任务完成；程序返回 `task_complete:false` 表示它没有建立整体完成结论，不表示主任务永远不能完成。最终结论由开发者核对实际交付范围和证据。

提问后继续不依赖答案的工作。只有所有剩余必要动作都被明确条件阻断时才交还用户；指出条件及影响，不把阶段转换、等待补充案例或局部通过当作停止条件。

形成方案时先说明目标、行为、取舍和验收，再单独组织文件、步骤、验证与恢复的实施计划。程序的 `plan` 保存实施计划，引用有效方案与行为来源；计划不是方案正确性的证明。按既有授权继续实施，无须为文档拆分重新索要批准。

前期讨论主动发现遗漏、原因和取舍，不等用户提供完整规格。已有认知形成后，后续只问新增事实、冲突及影响决定的新差异；沿用仍有效的来源和结论。

没有新增决策缺口时复用现行契约，不机械安排同一阶段序列。一个正本可用独立章节承载相关产出，按各自模板分别记录；不要把每个问题、来源清单和原始日志复制成另一份权威说明。先准备最终资料框架和验证命令，关键未知用针对性检查尽早揭示，最后同步资料后完成同版本检查。

锁前核对测试入口、实际后端、环境和整项生命周期预算（含启动、清理），缓存外置或显式禁用；按风险保留断言与测试分母，不为凑工具项数反复拼装测试。时限在计划中声明并随授权绑定，不能失败后在运行时悄悄放宽。计划范围确需改变时仍按当前恢复接口处理；重新规划的原因与原失败保留，回退次数不当作功能进展。

关键假设必须通过实验才能继续时，把实验作为当前小步完整运行本循环；先准备验证与停止条件，再完成实际配置、授权和锁定或隔离条件后执行。实验代码不自动成为正式实现。

讨论或方案形成不自动授权实施、对外发信、生产变更或付费资源创建。对当前授权内必要且可逆的本地工作继续执行；确需新授权时先准备可审阅的具体对象、影响和条件，再说明为什么需要该决定。既有授权不能补足未知业务规则。

## 失败与中断

| 情况 | 处理 |
|---|---|
| 来源缺失、互相矛盾或版本不明 | 标明不能判断的具体规则与影响，只暂停依赖它的动作；不能编造来源或把沉默当决定。 |
| 方案依赖未经核实的关键保证 | 先核验保证；无法取得证据时保持相关范围受阻，不用 Mock 成功代替真实保证。 |
| 执行中源或文档被外部修改 | 停止受影响写入，保存实际进度，由程序按归属处理重核验或恢复；不能覆盖变化后继续。 |
| 检查失败、环境不具备或恢复未验证 | 如实登记不同结果和下一动作；不删除断言、缩减分母或改需求制造通过。 |
| 进程中断、锁所有者失联或提交未结束 | 保留锁与状态供恢复流程核验，不手工解锁或新建同义任务绕过。 |

锁和一致性提交约束受管流程，不能阻止所有外部程序直接编辑文件；因此写入前后都要复核源与文档。解锁是最后一步，不是清除失败记录的手段。

## 程序接口与顺序

[字段、输入示例及限制](cli.md)按当前步骤读取。0.0.2对一个工程串行写入，精确文件范围覆盖代码与文档，不宣称并发范围写锁。

命令统一通过 `python3 <Skill根>/scripts/hs-dev.py --root <工程根> <command>` 调用。JSON 输入按程序与所选模板的实际字段准备，不能填写虚构来源、回答或执行结果。

| 当前动作 | 接口 | 核验重点 |
|---|---|---|
| 新工程初始化、接手已有工程 | `init`、`status` | 仅显式初始化新格式；已有中断、锁或源变化先处理，不自动迁移旧工作区。 |
| 找依据及创建当前交付 | `locate --query ...`、`read --path ... --start ... --end ... --digest ...`；`start --title ... --activity ID --scope ...` | 定位结果绑定当前内容；活动与范围明确，不把所有历史加入上下文。 |
| 登记来源与取得具体产出要求 | `source-add --record @source.json`；`template --activity ID [--output ID]`；`assess DELIVERY --record @assessment.json` | 记录可查来源及其适用条件；按模板 minimum 的固定项逐项给出理解、对话、未知、来源与判断，不能只凭材料存在声明达标。 |
| 提问、理解回答及反例复核 | `question DELIVERY --id ... --question ... --reason ... --options @options.json --recommendation ...`；`answer DELIVERY QUESTION --source SOURCE --understanding ...`；`reflect DELIVERY QUESTION --source ID,... --scenario ... --outcome supported\|reopen --reason ...` | 问题实际交给负责人；回答有真实来源，理解须用场景复核，不由模型制造确认。 |
| 检查就绪、登记方案及已有授权 | `readiness DELIVERY`；`plan DELIVERY --record @plan.json`；`authorize DELIVERY --source SOURCE --plan-digest ...` | 方案明确步骤、路径、验证、恢复、风险和来源；授权来源确实覆盖当前方案，不把授权绑定当重新索要许可。 |
| 锁定、执行与验证 | `lock DELIVERY`；`apply DELIVERY --changes @changes.json`；`run DELIVERY --checks @checks.json` | 锁后复核代码与文档基线。验证使用真实 argv，不拼接 shell；程序保存实际输出。 |
| 登记产出、一致性提交及最后解锁 | `produce DELIVERY --record @answers.json`；必要时 `record-output DELIVERY --record @output.json`；`submit DELIVERY`；`unlock DELIVERY` | produce 按所选模板的结构化回答渲染产物，实际内容和来源须满足要求；外部产物另行核验后登记。submit 不自动 Git 提交或部署，unlock 只在已提交或已回退状态执行。 |
| 进入下一活动 | `advance DELIVERY --activity ID` | 沿实际依赖在同一交付推进，保留已有理解、对话和进度，只补新缺口。 |
| 中断、回退与显式重建索引 | `resume DELIVERY`、`rollback DELIVERY`、`reindex` | 先核验实际归属、基线和恢复条件；不得用重建索引或解锁消除未完成事实。 |

来源、方案和内容变化时重新核对受影响关系与授权适用性。程序拒绝动作时保留具体原因与实际状态，不绕过门禁直接编辑执行记录。
