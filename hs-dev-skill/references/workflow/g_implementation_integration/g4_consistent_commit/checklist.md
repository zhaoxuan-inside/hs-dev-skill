# G4 验收规则

| ID | 内部活动 | 通过标准 | 验证方式 |
|---|---|---|---|
| G4.1 | 四层一致 | 本次受管源、相关文档/契约、索引发布及适用缓存属于可核验有效修订，验证证据对应同一源摘要；不以索引重建替代源验证，也不把应用自身所有缓存纳入无关治理 | 核对实际源摘要、验证记录、发布标识及一致性检查结果，检查读取/验证后相关内容漂移，不以命令成功证明同版本有效 |
| G4.2 | 提交协议 | 本次按执行协议完成凭据、恢复依据、修改/活动登记、真实验证及发布核验，相关确认失效与归属未遗漏；不重复实现或绕过协调机制，不将受管提交等同 Git commit、push 或部署 | 审阅实际操作与活动登记、依赖及确认有效性，依据协调入口核验发布/完成状态；外部编辑检查 reconcile 对象及验证范围 |
| G4.3 | 中断回滚 | 中断可识别且保留实际修改与恢复状态，继续或回滚依明确决定及协议处理；恢复仅覆盖归属范围并保护后续冲突，不能承诺必然可恢复或一律自动回滚，未核验状态不标安全/完成 | 对照操作状态与恢复依据核查中断可见性、归属和冲突保护；只有授权演练才记录恢复结果，无演练时说明依据及局限，实际中断交 continuity/recovery |
