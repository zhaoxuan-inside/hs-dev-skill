# B1 完整功能提取

## 目的与适用范围

将本次有效宏观能力和角色任务转化为可追溯的功能基线。完整性以约定需求和能力为分母，不以候选功能库或竞品全部功能为分母。局部新增/调整只核对受影响项，复用其他有效功能，不重新提取整个产品。

## 输入与输出

输入为有效能力、业务边界、需求来源、角色任务和已有功能台账；必要边界不清时返回具体上游缺口。输出包含功能标识、名称/用途、来源、适用角色、边界及纳入/排除/待定状态，以及相关能力映射和未决项。复用既有标识与记录，不强制新建编号体系或独立 PRD。

## 工作与核验

1. 核对本次需求分母、能力及已有功能，区分用户要求、已确认决定、新增建议与实现现状；代码已有能力不自动成为本轮要求。
2. 沿角色任务提取能表达业务目的的功能，保持可辨识粒度；一个页面可以承载多个功能，一个功能也可跨页面，不按页面数或技术模块机械拆分。
3. 关联来源、角色及边界，检查能力是否有功能承接、功能是否有依据、含义是否重复。发现遗漏先说明证据与影响，不自动增加交付承诺。
4. 根据本次场景选择相关通用能力判断纳入、排除或待定；仅实际需要时读取候选库对应条目，不加载整库，不把登录、搜索等常见能力当成必选。
5. 记录功能差异、关键待定项及受影响依赖，展示基线并按清单和当前模式核验确认。无关未知可说明限制后保留，依赖关键未知的详细设计不能继续猜测。

## 边界与交接

本活动不细化状态规则、交互、API 或数据库，不安排交付优先级和分期。功能范围状态不等于排期；不能将排除、待定或新增建议偷偷改成延期承诺。适用检查与确认满足后，按实际缺口转 B2 等活动；仍有阻断时交付影响及下一动作，不宣称详细设计已就绪。文档对账不证明功能已经实现或用户价值得到实证验证。
