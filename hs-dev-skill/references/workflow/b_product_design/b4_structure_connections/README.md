# B4 整体结构与功能关联

## 目的与适用范围

将本次相关功能组织成可达、可衔接的整体业务结构和角色旅程。局部改动只检查受影响节点、连接及必要上下文，不重做全部信息架构；已有有效关系可复用，但需核对是否受本次变化影响。

## 输入与输出

输入为有效功能基线、B2 行为、B3 交互及相关角色、入口和已有结构。输出为功能到结构/入口的映射、跨功能关系及代表旅程的演练结果。可用表格、流程、原型或文字表达，不强制每个功能一页或另建全站地图。

## 工作与核验

1. 明确本次分母和受影响关系，沿用功能标识；已排除、待定及建议项单独标记，不因整理结构自动纳入产品。
2. 将相关功能定位到导航、命令、调用、系统事件或其他实际入口，核对适用角色与前置条件。自动/后台功能说明触发与结果归属，不为覆盖检查增加虚构页面。
3. 沿功能连接核对业务信息、状态、权限及上下文传递，说明完成、返回、退出和失败后进入哪里；共享术语与规则保持一致。业务行为缺口返回 B2，交互缺口返回 B3，不在关系图中悄悄补新规则。
4. 按本次目标选择首次使用、核心成功及适用失败恢复旅程，明确角色/初态、起点、步骤和终点。检查无入口、无下一步、上下文丢失、循环死路及权限冲突；不强制局部变更重演所有用户路径。
5. 记录所用流程、原型或示例及实际观察，将未演练、模拟和真实系统结果分开。展示连接、冲突及未决影响，依清单和当前模式核验确认；仅有目录树或技术调用图不足以证明业务旅程完整。

## 边界与交接

本活动定义业务/信息结构和功能关系，不决定技术模块、路由实现、数据库或部署拓扑；相应实现边界交由工程及框架设计。设计旅程通过不证明真实集成、用户可用性或全部可访问性达标。关键连接存在分歧时保持阻断并给出下一动作；适用标准及确认满足后按实际缺口进入 B5 或后续设计，不自动新增功能、实施或发布。
