# H2 交付与恢复验证

## 目的与适用范围

验证本次实际交付物能否按约定使用，以及本次要求的恢复保证是否有对应证据。按真实交付形态和风险选择检查，不强制局部文档改动验证安装包，也不因本活动自动回滚工作区或执行生产故障演练。

## 输入与输出

输入为明确交付范围、目标产物/环境、使用说明、恢复契约及已有有效结果。输出记录交付与适用恢复场景的条件、实际结果、版本和局限，附阻断及下一动作。已有证据可核实适用性后复用，不重复进行无关全量检查。

## 工作与核验

1. 确定实际交付形态、支持范围及判据，定位最终产物而非仅开发源码；区分库、服务、客户端包、文档等使用路径，必要条件不清先澄清。
2. 在授权目标或足够代表的隔离环境按说明执行必要安装、配置、启动和代表使用路径，记录实际步骤、结果和差异；开发启动、构建或包结构校验各有边界，不自动证明最终环境可用。
3. 仅对本次要求的恢复保证核对对象、可恢复依据、授权和安全条件，复用恢复技能/协议；明确文件、状态、索引及适用外部资源的实际范围，不能从文件快照推定数据库或远程副作用可恢复。
4. 需要演练时使用隔离副本或专用测试资源选择实际风险场景，检查恢复后内容/状态及冲突保护，并说明不可逆限制。未演练时记录未验证，不以计划、凭据撤销或命令成功证明恢复正确；没有授权不触碰真实用户数据。
5. 核对各项源修订、产物标识/摘要、环境及依赖，相关变化后复核受影响证据。不同平台或包可分别记录，但均须能追溯到相应交付版本，不能强行当成相同二进制或外推全部组合。
6. 汇总实际结果、未覆盖范围和风险，按当前模式处理确认；未执行、跳过、取消或证据过期不记通过，关键交付/恢复条件不足保持阻断。

## 边界与交接

本活动验证约定交付和恢复能力，不自动安装到用户正式环境、迁移生产数据、清理记录或发布。具体缺陷交负责过程，适用标准及确认满足后转 H3 或按诉求交付；验证通过不代签最终人工验收，也不免除恢复操作的冲突与授权要求。简单范围直接回复或复用已有记录，不强制新增演练报告。
