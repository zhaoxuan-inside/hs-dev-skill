# H1 完整性对账与现状核验

## 目的与适用范围

对本次指定范围核对实际现状、覆盖和一致性。可服务交付核验，也可为修复/重构建立必要事实基线，但不因此启动全项目调查或读取全部 A～G 资料；已有有效映射和证据直接复用。

## 输入与输出

输入为本次核验对象、明确范围和有效约定，以及相关代码、配置、材料、证据及确认状态。输出关联现状与约定差异、覆盖结论、版本一致性、问题影响和下一动作。范围不清先核实，不自行选取较小分母或把所有历史建议纳入要求。

## 工作与核验

1. 明确本次目的和分母，区分只读评审与需要受管登记的验收；只读评审不创建任务、修复索引或写确认。
2. 从实际对象及相关入口核实现状，结合必要运行证据，区分需求、已观察行为、推断与疑似缺陷；代码和文档冲突说明依据与影响，不自动认定现状正确或错误。
3. 沿需求、功能、适用设计、任务、实际修改和证据对账，检查遗漏、孤立及不适用依据。项目无需的产物不补造，简单内部方法可沿调用链验证，不为数量或表格牺牲真实覆盖。
4. 核对相关契约、源摘要、派生定位和证据适用条件，沿实际消费依赖判断确认是否有效；相关变化按统一机制处理，无关修改或重建索引不全量撤销成果，索引也不能证明源已正确验证。
5. 缺少专业判断时按需调用 testing、governance 或相关领域技能，传递当前范围及只读限制；补测或修复须符合已有授权，不自动扩大审计或重走产出过程。
6. 展示逐项结果、证据、未知及影响，按当前模式处理适用确认。未验证、材料缺失或过期不能记通过，明确问题返回哪个负责活动及下一动作。

## 边界与交接

本活动不直接裁剪需求、修改业务或代替实际交付/恢复演练。适用标准满足后仅报告本次核验结论，关键遗漏/冲突未解决保持阻断；按实际缺口转 H2/H3 或负责过程。完整性对账不等于功能已实现、生产可用或人工验收完成，简单结果可直接回复或更新已有记录。
