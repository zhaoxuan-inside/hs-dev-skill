# C3 技术与方法决策

## 目的与适用范围

解决本次确有缺口的技术或工程方法决定。没有实际选型问题时说明沿用依据，不重新比较整套技术栈；技术名称和方法目录只提供候选，不代表默认推荐或强制采用。

## 输入与输出

输入为相关质量目标、核实约束、关键风险结论、现有工程及团队/维护条件。输出说明沿用或选定方案、实际版本与支持条件、依据、取舍、影响对象和未决项。需要变更技术时明确迁移和退出边界，但不在此自动安排完整交付计划或实施迁移。

## 工作与核验

1. 明确要解决的问题和评价约束，先检查现状；已有方案满足目标时保留，不以流行度、个人偏好或新技术存在作为换型理由。
2. 必要时选择少量能满足硬约束的候选，用相同运行场景和维护条件比较，涵盖本次相关的集成、学习、运行、迁移及退出成本。没有比较就不编造落选方案或评分。
3. 对涉及的具体版本、平台支持、许可、维护策略及成本等外部事实按需核对官方来源并记录时间；已有有效证据可复用，不把本地示例当成当前支持承诺。关键未知返回 C2 取得必要证据。
4. 工程方法按问题采用或局部采用，说明具体措施与代价；不强制遍历 DDD/TDD 等全部方法，也不为展示模式增加层级或测试。项目明确规则仍须遵守，真实冲突由负责过程裁决。
5. 形成唯一有效决定，区分当前方案、建议、实验候选和历史记录；关联受影响契约、验证依据、迁移条件与剩余风险。展示结果并依当前模式确认，不能将实验成功自动写成正式采用。

## 边界与交接

本活动不擅自改变产品规则、降低质量要求或扩充支持范围，不自动安装依赖、购买资源、换栈或迁移数据。关键可行性或必要取舍未确定时保持依赖阻断；适用标准与确认满足后按具体问题转架构、工程设计或规划，不默认展开所有后续活动。决定可追溯不等于方案已在生产验证，文档记录不代替真实人工确认。
