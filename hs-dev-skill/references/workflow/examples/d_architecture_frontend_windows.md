# D 架构设计范例：Windows 草稿恢复

> 虚构案例；共用行为和服务端契约见 [D 共用架构](d_architecture_common.md)。实现验证见 [G Windows 实现](g_implementation_frontend_windows.md)。

## 平台行为

- 编辑窗口关闭前检查本地保存是否完成；若仍有未落盘内容，按产品规则阻止关闭或明确提示。已落盘但未同步的草稿允许关闭，并在下次启动继续同步。
- 若应用支持托盘常驻，关闭窗口和退出进程是不同操作；托盘状态、菜单命令及用户偏好决定实际行为，不默认把关闭改成隐藏。
- 多窗口编辑同一草稿时使用共享版本检查；窗口间消息仅用于刷新视图，持久化仓库仍是权威状态。
- 系统通知只报告有意义的同步结果，不在通知内容泄露草稿正文。

## D4 框架边界

窗口生命周期层发出关闭/退出意图；草稿服务报告本地写入状态；应用层依据已确认的产品规则决定允许关闭、提示或继续后台工作。安装类型、用户数据目录、单实例策略和自动启动均须先确认，不能从 Windows 平台本身推定。

平台特定检查归入 [G Windows 实现范例](g_implementation_frontend_windows.md)，并按实际支持的 Windows 版本、架构、安装方式和用户权限记录结果。
