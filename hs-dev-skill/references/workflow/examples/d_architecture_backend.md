# D 架构设计范例：后端草稿同步 API

> 虚构案例；产品规则、数据定义和客户端责任见 [D 共用架构](d_architecture_common.md)。实现验证见 [G 后端实现](g_implementation_backend.md)。

## 契约落实

`PUT /drafts/{id}` 接收草稿内容、可选基础服务端版本和客户端 mutation ID。服务端对相同 mutation ID 返回同一逻辑结果；版本仍匹配时原子写入新版本，版本过期时返回冲突及当前版本。超时后客户端可安全重放同一 mutation ID。

本例未规定认证、租户隔离、配额、内容加密、保留期限或审计策略；真实设计必须从项目要求、现有身份模型和部署约束获得决定，不能照抄为默认规则。

## 模块边界

| 模块 | 责任 | 不变量 |
|---|---|---|
| HTTP handler | 校验请求格式、身份上下文并映射响应 | 不承载并发控制逻辑 |
| Draft service | 执行幂等与版本条件，返回已保存/冲突结果 | 冲突时不覆盖当前内容 |
| Repository | 原子读写草稿与 mutation 结果 | 版本检查和写入处于同一一致性边界 |
| Storage adapter | 映射项目实际数据库/存储技术 | 不把存储错误误报为业务冲突 |

## 任务与验证

| 任务 | 验证场景 |
|---|---|
| 请求/响应校验 | 缺失字段、超长内容和无效版本返回稳定错误语义 |
| 幂等处理 | 同一 mutation ID 重放不产生重复副作用 |
| 并发控制 | 两个请求基于同一旧版本写入，最多一个更新成功，另一个收到冲突 |
| 故障处理 | 存储超时/事务失败不返回虚假的成功或冲突 |
| 数据隔离 | 按实际认证与租户要求验证跨用户访问边界 |

由实际数据库、事务隔离级别和服务部署形态决定并发测试方式；契约测试通过不等于生产环境容量或可用性已验证。
