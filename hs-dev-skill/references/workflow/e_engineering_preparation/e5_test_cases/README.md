# E5 测试用例构建

## 目的与适用范围

为本次任务建立能判断有效契约的验证用例及执行条件。按行为和风险选择，不强制所有局部修改新增测试或构建完整测试体系；优先复用仍有效的用例，具体专业方法由 testing 提供。

## 输入与输出

输入为有效行为、相关工程契约、质量判据、受影响对象及现有测试设施。输出按需要包含用例来源、初态/输入、操作、预期、断言、执行入口、环境/数据和覆盖映射。可采用项目既有测试、人工操作或适用检查，不强制新建用例文档和框架；设计计划、已构建用例和实际运行结果分别标明。

## 工作与核验

1. 固定本次验证范围及源版本，核对规则和实际对象，区分有效契约与实现现状。必要预期未知时返回负责活动，不能通过照抄代码行为制造断言。
2. 根据需求、边界、异常及质量风险选择有区分力的用例，定义初态、输入、操作和可观察结果；必要时检查不变量与副作用，不只比较返回值。不为凑数量穷举无关状态或测试框架本身。
3. 与 testing 选择行为、契约、集成或其他适用层次，明确真实资源/替身边界、数据隔离、清理和可重复条件；具体测试数据或替代服务有缺口才转 E6/E7，不默认新建服务。
4. 按当前阶段和授权核实可执行性。TDD 或缺陷回归需要时确认测试因目标行为失败；语法、导入、配置或环境错误不算有效行为失败。业务尚未实现的预期失败应如实记录，不能标通过，也不为本活动自动补业务实现。
5. 将本次任务、行为及受影响对象映射到直接或调用链验证；简单内部方法无需独立用例，但间接检查应能判断其相关效果。未实现对象和拟补测试标为计划，无法验证部分说明缺失条件。
6. 记录实际命令/操作、环境、预期与结果和证据，审阅遗漏及局限并按当前模式确认；测试未运行、跳过、取消或超时不得记通过，不靠删断言或放宽预期使结果变绿。

## 边界与交接

本活动构建和核验用例，不代替 G2/G3 的实现后验证或 H 阶段验收。用例准备就绪不代表业务通过；设计阶段缺少业务实现可以保留明确待执行状态，但环境损坏或关键预期未知不能宣称可执行。适用标准及确认满足后按缺口转数据/服务/配置准备或实施，不自动安装新设施、访问生产资源或发布。
