# E2 接口契约设计

## 目的与适用范围

为本次受影响的调用边界定义双方可遵循、可判断的接口契约。按实际协议处理 HTTP、消息、命令或其他交互，不默认新增 Web API 或协议层；只展开相关操作及消费者，复用有效契约。

## 输入与输出

输入为有效行为、数据语义、模块协作、实际协议及兼容要求。输出明确操作入口、输入/输出、访问条件、错误、副作用和适用交互语义，附示例、版本、权威来源及验证结果。已有 OpenAPI、Schema、类型或其他机器定义时保持单源并同步必要派生说明，不强制另写完整 Markdown 或创建机器文件。

## 工作与核验

1. 定位提供方、消费方和本次操作，核对实际协议及版本；区分现状、有效要求和建议。业务结果、权限或数据含义缺失返回负责过程，不靠状态码或技术默认补规则。
2. 明确适用入口、载荷及元数据的类型/格式、单位、必填、缺失、空值、默认和约束；定义成功、失败与副作用，选择能说明关键边界的示例，不暴露真实凭据或用户数据。
3. 仅在涉及时说明认证授权、资源/租户归属、重复与幂等、分页/排序、重试、流式结束或异步完成语义。区分调用方可做什么与提供方承诺什么，不由客户端禁用按钮、重试配置或 Mock 行为推定服务端保证；详细时序和运行机制交 E4。
4. 对外部服务核对实际官方或绑定契约的版本、错误和能力限制，未知明确标记。共享规则与 E1/B2 对账，协议细节不能反向改变产品行为。
5. 核对权威契约、示例、调用方/提供方和派生说明一致性，按项目选择机器校验、契约检查或授权真实集成。记录版本、条件、命令/操作、实际结果及替身范围；契约变更说明影响消费者和兼容条件，不默认删除旧版本或承诺零影响。
6. 展示决定、验证和未决项，按当前模式确认；必要语义或兼容决定未定时保持依赖阻断，继续独立工作。

## 边界与交接

本活动不自动实现或调用生产接口、发送消息、创建资源、修改鉴权或迁移客户端。静态校验通过不等于真实服务符合契约；不能接入时明确未验证部分，不用模拟冒充集成。适用标准及确认满足后按实际缺口转 E3/E4、测试或实施，不以接口文档完成宣称业务已实现。
