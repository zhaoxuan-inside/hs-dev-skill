# E9 工程准备度核验

## 目的与适用范围

核验指定范围是否具备实施所需的契约、验证和环境条件。仅在用户要求或实际准备度缺口涉及本活动时使用，不作为每项局部修改必走门禁；不因 E9 引用多个上游就重做 E1～E8。

## 输入与输出

输入为明确待实施对象和范围、有效上游决定及本次适用工程契约、用例、环境和证据。输出为逐项准备度结论、依据、阻断、未验证/不适用说明及下一动作。缺少明确范围时先核实，不自行缩小对象集合以宣布就绪。

## 工作与核验

1. 明确本次实施目标及必要输入，按实际对象选择数据、接口、方法、运行、测试、替身或配置检查；不存在的需求不强造产物，已有有效结果直接引用。
2. 核对必要契约可定位、语义一致且可实施，用例具有可判断预期，环境与装配条件满足本次需要。缺口返回具体负责活动，不在核验中暗改业务规则或补全全部设计。
3. 按风险和当前阶段核验相关启动、测试入口及依赖；业务尚未实现可以出现明确预期失败，不要求实现前测试全绿，但语法、导入或配置错误不能冒充有效失败。未执行计划或只有文档不能证明环境可运行。
4. 区分本次实施所必需的真实边界与可暂由替身支持的部分，说明模拟范围及后续真实集成条件。缺少关键外部保证且会推翻实现时保持阻断，非阻断接入未知可明确交接，不以全 Mock 证明集成就绪。
5. 复核实际消费输入、产物及证据的版本、适用环境与依赖；相关变化导致的失效按统一机制处理，不因无关修改或索引重建全量撤销已有成果。
6. 展示范围、检查、材料、阻断和剩余风险，按当前模式确认；必须条件满足才报告本次准备就绪，待定或未验证影响结论时明确受限或未就绪，不以任务命令成功替代核验。

## 边界与交接

本活动不代替 G 阶段的行为/集成验证和 H 阶段验收，不自动安装服务、创建环境、迁移数据或实施业务。准备度完成不等于功能实现、质量达标或发布授权；沿当前诉求与已有授权转规划或实施。简单范围可直接回复或复用结果记录，不强制新增准备度报告、阶段文档或独立台账。
