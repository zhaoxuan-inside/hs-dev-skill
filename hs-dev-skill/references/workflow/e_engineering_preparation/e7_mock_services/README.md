# E7 Mock服务构建

## 目的与适用范围

仅在本次用例需要验证跨协议客户端行为，且已有设施不能满足替代需求时构建 Mock 服务。外部暂不可用不自动触发独立服务；纯方法测试可使用合适替身，无替代需求说明不适用，不额外增加技术栈。

## 输入与输出

输入为有效外部契约、测试场景、实际协议、已有替身及客户端装配条件。输出为必要服务或既有设施的场景配置、覆盖范围、启动/隔离/清理及切换方式、验证结果和真实接入缺口。协议可以是 HTTP、消息或其他实际边界，不将所有依赖改造成 HTTP。

## 工作与核验

1. 与 testing 核对本次验证目的，优先复用已有替身；只有实际协议、序列化、错误或连接行为需要独立边界时才选择服务形式，不为清单部署无关设施。
2. 从有效契约定义所需操作、输入输出、错误和场景数据，来源/版本可追溯；未知明确标记，不能根据自己写的服务补造第三方保证。数据缺口复用 E6 方法，不复制真实凭据或未授权数据。
3. 按需提供可控错误、延迟、断开或重复等场景，说明故意无效行为和预期；模拟的时序及资源限制只支持对应条件，不承诺等同真实提供方。
4. 经项目既有配置或依赖装配切换，网络服务按需要配置地址；正式业务不含 Mock 兜底或模拟分支，不为切换改业务规则。明确隔离、启动/停止、端口或命名空间及清理范围，控制场景的入口不暴露为正式能力。
5. 在授权环境通过实际客户端或协议检查运行代表场景，核对请求响应及相关失败处理；记录版本、操作、预期、实际结果和局限。服务可启动不等于所有契约已验证，契约自洽不证明真实集成。
6. 列明真实接入仍需的验证及条件，按当前模式展示并确认；真实服务不可用时保留未验证部分，不自动调用生产、创建付费资源或发送外部消息。

## 边界与交接

本活动不实现真实第三方服务、不替代 E2 决定接口或 E4 决定运行语义，也不改变正式业务路径。关键契约、装配或隔离未知时保持依赖阻断，非阻断模拟缺口说明影响。适用标准及确认满足后按实际需要转配置、集成或实施，不以全 Mock 通过宣称端到端真实协作完成。
