# G3 增量集成

## 目的与适用范围

在当前切片具备条件时验证实际模块、资源及用户/业务路径的协作，尽早发现集成问题。只覆盖本次受影响边界及必要回归，不要求每个局部修改跑全系统或所有设备；没有集成边界变化时可复用有效证据并说明依据。

## 输入与输出

输入为实际切片、有效边界契约、G2 相关证据、提供/消费方版本及目标环境。输出记录集成、代表端到端和回归结果，附资源类型、替身覆盖、清理和未验证条件。已有有效结果可按版本及条件复用，测试计划或服务可启动不能替代集成执行。

## 工作与核验

1. 沿本次差异定位模块、协议、配置、数据及平台边界，核实各端版本与实际资源；识别需要真实验证的保证，不从单元测试或 Mock 自洽推定外部契约成立。
2. 与 testing 和相关领域技能选择最小足够集成场景，明确初态、输入、预期结果及副作用；使用授权的隔离或沙箱环境，真实集成不等于必须访问生产。外部发信、付费资源和破坏性数据操作不自动获授权。
3. 按当前切片实际入口及时验证代表成功和风险相关失败路径，核对最终可观察结果、上下文与资源状态。说明从哪里到哪里是端到端，哪些边界仍为替身；不能把一个 API 成功代表全部用户路径。
4. 基于实际依赖选择共享契约、调用方及相关行为回归，复用未受影响的有效证据；简单内部方法允许间接覆盖，不能仅靠目录或测试数判断影响。关键环境不可用时说明阻断，不缩减范围后假称全通过。
5. 分类新增缺陷、契约冲突、既有失败、环境及非确定性问题，按当前授权交回实施、debugging 或设计处理。保留首次失败和后续结果，不通过重跑、放宽断言或删路径掩盖问题。
6. 记录命令/操作、源和各端版本、环境、初态、预期及实际结果、退出码或观察和证据；清理仅限本次归属测试资源。相关修复或契约变化后复核受影响集成，展示剩余风险并依当前模式确认。

## 边界与交接

适用集成及回归无未解释失败、关键真实边界已验证后，才报告本次范围通过；模拟或环境缺失时明确受限结论，必要项保持阻断。结果不等于生产可用性、产品完整或人工验收完成，不自动部署或发布。按实际状态转 G4 或负责修复活动，不推迟应做的集成，也不把无关检查机械重复。
