# G1 切片实现

## 目的与适用范围

落实当前已明确切片的必要代码和资源修改。按当前任务和实际影响工作，不加载未来切片或全部上游；实现过程由 implementation 编排，具体方法由相关领域技能指导，不在此重复其全套执行协议。

## 输入与输出

输入为当前任务、有效契约和通过标准、相关代码及工程约定，并满足主入口规定的安全和恢复条件。输出为实际修改、对象归属及必要同步资料，附针对性检查证据和未验证项。任务或关键规则不清时补具体缺口，不能凭实现便利猜测业务决定。

## 工作与核验

1. 修改前核实本次目标、授权、必要上游和通过标准，检查已有修改及其归属；按执行协议取得写入条件，不绕过门禁覆盖他人工作。
2. 检索并复用符合意图及契约的已有实现，沿用项目结构和工具约定；仅因相似度不强制复用，也不为局部任务新增无依据抽象、依赖或技术栈。
3. 按可验证行为小步实现，与 testing 按风险选择必要的先失败检查；低影响修改不强制新增测试。正式路径不包含测试数据或模拟兜底，但项目有效兼容承诺必须保留，不能将兼容代码一概视为应删除。
4. 记录实际新增、修改、删除和移动的对象及资源，核对业务常量语义；同步相关权威契约和必要派生资料，生成产物从其源更新，不把计划对象冒充实际修改。
5. 执行足以反馈当前变化的针对性检查，区分行为失败、环境错误及未执行，后续 G2/G3 按需要展开。意外业务变化先定位原因，契约确需改变交回负责过程；独立缺陷或重构不顺带混入。
6. 展示实际结果、源版本、检查及剩余条件，按当前模式处理适用确认。中断或漂移交 continuity 和恢复能力，不以手动标记安全继续写入。

## 边界与交接

代码存在不等于切片行为已验证，针对性检查不自动代替必要集成和验收。关键实现/契约阻断未解决时不能报告完成；仅部分验证须限定结论。按实际需要进入 G2/G3/G4，不自动 Git commit、push、部署或发布，受管变更发布仍遵循执行协议。
