# G2 切片验证

## 目的与适用范围

验证当前已实现切片的适用行为及工程约束。复用 testing 的选择、失败分类和证据方法，先做针对性检查再按实际风险扩展；不把局部变更升级为全项目测试或全面安全审计，也不推迟必要集成到最后。

## 输入与输出

输入为实际修改及源版本、有效契约、通过标准、用例和环境，附已有失败基线。输出为逐项实际结果、证据和局限，说明未通过、未验证及下一动作。准备好的用例或计划不是实际结果，代码已写也不能作为通过依据。

## 工作与核验

1. 核对本次变化、有效预期、测试入口与环境条件，沿受影响行为选择正常、边界、异常及不变量检查；低影响修改不为凑数量补测试，已有有效检查可复用。
2. 依实际目标运行自动或人工验证，观察结果及相关副作用；TDD/回归需要先失败证据时核对失败确因目标行为，不将导入、配置和环境错误当作有效红阶段，不伪造历史执行。
3. 执行项目相关类型、静态、构建及适用资源/安全检查，区分其证明范围；构建成功不证明交互、数据隔离或真实外部协作已通过，实际集成缺口转 G3。
4. 分类行为缺陷、既有失败、测试预期错误、环境故障及非确定性问题，保留原始结果和条件。修复在当前授权内进行，独立缺陷交 debugging；不靠删断言、放宽预期或一次重跑成功掩盖未解释失败。
5. 记录对象、源版本/摘要、时间、环境、命令或操作、预期与实际结果及证据位置；自动命令保留退出码和必要输出，人工操作保留步骤与观察。凭据和不必要用户数据不进入记录，Mock 与真实结果分别说明。
6. 对修复或其他相关内容变化重跑受影响检查；无新变化或未决风险时不机械重复全部验证。展示结果与剩余条件，按当前模式处理确认，不把未执行、取消、超时或跳过记为通过。

## 边界与交接

本次适用检查无未解释失败且必要结果有效后才报告限定范围通过；未验证项说明影响，关键条件缺失保持阻断。测试通过不等于产品完整、真实集成或人工验收完成，不能自动授权受管发布、Git 操作或部署。按实际缺口转 G3、G4 或负责修复过程，简单任务复用结果记录，不强制新增报告。
