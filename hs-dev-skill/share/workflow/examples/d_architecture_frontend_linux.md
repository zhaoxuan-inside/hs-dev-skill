# D 架构设计范例：Linux 桌面与本地草稿

> 虚构案例；共用行为和服务端契约见 [D 共用架构](d_architecture_common.md)。实现验证见 [G Linux 实现](../../../skills/hs-dev-implementation/SKILL.md)。

## 平台行为

- 本地草稿目录遵循应用选择的用户数据约定，并通过平台/框架能力获取路径；不硬编码某个用户目录。
- 关闭窗口、退出应用和桌面会话结束的处理遵循明确产品规则；进程终止时仍以已完成的原子本地写入为恢复基础。
- 若使用桌面通知或文件门户，权限/服务不可用时同步仍可工作，界面给出可理解状态，不把可选系统服务变成保存前置条件。
- 显示后端、桌面环境与打包格式可能影响窗口和系统集成；Wayland、X11 或兼容层的通过结果不能互相替代。

## D4 框架边界

草稿存储和同步保留平台无关接口；路径、通知、门户和包元数据放在适配层。是否使用 Qt、GTK、Electron、Tauri 等沿用仓库现状，范例不要求更换框架。

发行版、桌面环境、显示协议、路径权限和包格式验证见 [G Linux 实现范例](../../../skills/hs-dev-implementation/SKILL.md)；未覆盖组合应标记未验证。
