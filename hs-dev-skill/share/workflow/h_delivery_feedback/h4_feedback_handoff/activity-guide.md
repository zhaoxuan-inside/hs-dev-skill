# H4 反馈与后续

## 目的与适用范围

把本次反馈转为有依据的后续处理，并保留足够续做的最小上下文。只处理实际反馈及影响，已有结果和任务有效时复用；没有新动作不为了闭环自动创建任务或重开所有阶段。

## 输入与输出

输入为真实反馈、对应对象/材料及版本、有效决定、任务/工作区状态和已有授权。输出说明反馈分类、影响、负责过程或活动、保留成果、未决项和下一动作。需要交接文档时可按需使用[交接模板](../../../templates/handoff.md)，简单反馈直接回复，不强制新建报告。

## 工作与核验

1. 关联反馈来源、原意、对象及相关版本，区分要求、建议、疑问和实际确认；不把助手归纳冒充用户原文。范围或意图存在影响执行的歧义时澄清，不从简短反馈擅自扩大授权。
2. 对照有效约定和现状区分疑似缺陷、需求变化、行为保持的结构改进或咨询；证据不足保留待核实。缺陷交 debugging，需求/约束变化按 discovery/continuity 处理，重构交 refactoring，解释交 exploration，不在分类时宣称根因已证实。
3. 沿实际依赖判断受影响的契约、实现、证据和确认，按统一机制处理失效；保留无关有效成果，不因反馈重载全部历史或重做全部阶段。
4. 给出具体下一动作、必要输入、继续条件及阻断；已有授权下交回负责过程继续，未授权建议止于建议。任务登记、写入及恢复仍遵循安全门禁，不新建同义任务绕过未完成或漂移状态。
5. 交接时保留目标、范围、有效决定与来源、当前过程/活动、实际进度、源版本和工作区状态、产物与证据引用、未决项及影响。恢复依据仅记录已核实标识和限制，不嵌入快照正文，不把未知状态写成 SAFE 或可回退。
6. 核对下一执行者能定位必要材料并开始首个动作，说明证据局限和缺失条件；不复制全量对话、日志、代码或秘密，不将摘要替代必须读取的有效契约。必要确认依当前模式处理，不重复确认有效决定或代签。

## 边界与结束条件

分类、影响和下一动作清楚，必要续做信息有有效定位后可结束本次反馈处理；仍有歧义或阻断则说明具体缺口。交接完成不表示原任务、修复或新增需求已完成，不自动承诺时间、创建资源、执行恢复、提交 Git 或发布。后续按实际负责过程和已有授权执行，不把反馈循环变成固定全流程。
