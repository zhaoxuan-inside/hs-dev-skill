# H3 验收

## 目的与适用范围

按当前模式完成本次明确范围的验收责任，保留真实确认来源。规则、材料与决定以[统一验收协议](../../../core/acceptance.md)及其模块为准，本活动不另造确认机制，不把模型核验统一称为人工验收。

## 输入与输出

输入为当前实际模式、适用清单结果、明确范围、材料/证据及实际依赖版本。输出是与当前范围绑定的确认或拒绝/暂缓/修复记录，以及完成状态、阻断和下一动作。单纯只读评审可返回结论，不自动创建任务或写入确认。

## 工作与核验

1. 核对本次对象、范围、模式和适用结果，复用仍有效确认；先处理关键材料缺失、证据过期及未解释失败，不通过提前询问确认掩盖检查缺口。
2. 按统一机制登记必要主要材料，日志仅作检查证据，不自动扩成独立材料卡。展示具体范围、进度、检查摘要、材料及审阅重点，风险和未决项可见；不只展示一个模糊“是否通过”。
3. mute 按模块记录模型来源，activity/stage 按相应范围获得真实人工反馈。已有一次明确范围反馈覆盖已展示材料时依协议复用，不再追加相同确认；恢复或继续的决定不自动等于验收通过。
4. 反馈绑定实际材料 ID 与当前 view_digest，记录真实原文及来源；未提及项不变，拒绝有原因，暂缓/修复另有下一动作。沉默、等待、助手建议和转述不代替实际确认，defer 不等于 PASS 或 NA。
5. 核对清单、材料、实际依赖和证据摘要仍有效。视图过期或受消费契约变化时按模块拒绝失配写入并重新展示受影响内容，不手工改摘要或全量撤销无关确认。
6. 完成前重新核对适用项、阻断和确认责任，满足才通过现有完成机制标记完成；否则报告具体缺口、负责过程与下一动作，不能用任务命令成功或模型结论代替真实验收。

## 边界与交接

验收不自动授权新需求、Git 提交、push、部署或发布。反馈缺陷返回负责修复过程，需求变化由相应过程处理；后续按需要转 H4，不重走全部阶段。验收结论限定实际范围和版本，暂缓/拒绝保留未完成状态；简单任务复用现有结果和材料，不强制新增验收报告。
