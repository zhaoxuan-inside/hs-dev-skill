# C1 质量目标定义

## 目的与适用范围

将本次相关质量要求转成可判断、可验证的目标，为技术决策和后续验证提供依据。按风险选择性能、可用性、安全、可维护性、可访问性等实际涉及属性，不加载全部质量目录；已有有效目标直接复用，局部变更仅复核受影响条件。

## 输入与输出

输入为有效业务行为和场景、质量要求来源、已有基线及资源/运行约束。输出为质量场景、目标判据、必要权衡和验证计划，附未知与阻断。缺失的产品要求由负责过程澄清，工程可核实的条件先查证，不凭经验编造指标或测量结果。

## 工作与核验

1. 从真实使用和失败风险识别本次质量目标，记录来源及适用对象，区分硬约束、期望与建议；不把选用某框架、缓存或加密等措施本身当成目标达成。
2. 对每项关键目标说明触发、环境、受影响对象和期望响应；适合量化的明确指标、单位、阈值及相关统计口径，定性目标采用可重复审阅标准。没有明确数值依据时标记待定，不伪造精度。
3. 核对目标冲突及资源、成本和体验代价，说明哪些已决定、哪些需裁决；不擅自降低有效要求，也不要求所有属性同时最大化。此处的质量权衡不等于交付分期。
4. 与 testing 及相关领域能力选择可行验证方式，明确环境、数据/样本、负载、测量或审阅步骤及通过条件；按需说明基线和代表范围，不强制所有目标采用压测或数字指标。
5. 按清单检查目标和验证计划是否可判断，展示取舍、未知及影响并依当前模式确认。必要最小实验只在授权范围执行，实际结果与计划分别记录；可能推翻目标可行性的未知交由 C2 核实，不用模拟冒充达标。

## 边界与交接

本活动定义要达到什么以及如何判断，不默认选定技术机制、安装监控、开展全面安全审计或修改生产系统。关键目标、判据或取舍未定时保留相应阻断；非阻断未知说明验证条件和下一步。适用检查及确认满足后，按实际缺口转 C2、C3 或架构设计；目标定义完成不证明实现质量已达标，不自动发布或承诺服务等级。
