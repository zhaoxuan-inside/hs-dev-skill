# C2 技术约束与风险

## 目的与适用范围

核实本次会影响技术决定的约束和未知，避免后续设计建立在关键猜测上。只调查当前对象与风险，不自动开展全项目审计、全面压测或新技术选型；有效现状和已有核验结果可按版本及条件复用。

## 输入与输出

输入为有效业务契约、质量目标、相关代码/配置、运行环境及已有平台和依赖证据。输出记录约束来源、条件、风险假设、最小核验结果及剩余风险处置。实际工程可确定的信息先核实，外部事实按需查证；缺失产品取舍交回负责过程，不通过技术调查自行裁剪需求。

## 工作与核验

1. 定位本次运行平台、依赖版本、部署和外部边界，区分已证实限制、明确要求、偏好及假设。涉及成本/容量时注明来源、计量条件和估算假设，不从目录示例编造当前价格或配额。
2. 说明哪些未知可能推翻目标可行性、方案或关键边界，按影响及依赖选择先核验的问题；风险排序服务于技术调查，不等于产品交付分期。
3. 为关键假设选择最小且有区分力的证据：可用配置/契约核验时不强制写实验，必须运行才能判断时明确环境、输入、判据与停止条件。按需与 testing 及领域技能协同，不把验证扩展成正式业务实现。
4. 在授权范围执行必要检查，记录版本、操作、实际结果及局限；付费资源、生产访问或破坏性实验不自动获得授权。条件不足时说明缺口并保持依赖阻断，不靠反复重跑或模拟成功抹去风险。
5. 对剩余风险记录触发、影响和下一动作，区分规避、缓解、继续验证及需要明确接受的风险；接受或降低要求须有决定依据，不能由模型以“可接受”代签。展示结果并按当前模式核验确认。

## 边界与交接

本活动提供事实和风险证据，不默认选定技术栈、部署资源或修改业务规则。单环境、单样本或 Mock 结果仅支持对应条件，不证明生产容量、可靠性或真实外部集成。关键未知未解决时不能宣称设计可行；非阻断未知给出适用条件和后续核验。适用标准及确认责任满足后按具体缺口转 C3 或相应设计，不自动实施或发布。
