# E2 验收规则

| ID | 内部活动 | 通过标准 | 验证方式 |
|---|---|---|---|
| E2.1 | 接口详情 | 本次操作的协议入口、输入/输出、类型/格式、必填/缺失/空值/默认、成功与错误及副作用明确并关联业务语义；示例符合契约，不强制所有接口使用 HTTP 或新建 Schema 文件 | 逐操作核对有效业务规则、协议及数据定义，用相关正常/错误示例检查类型、缺失/空值、默认和结果，记录未确定语义 |
| E2.2 | 访问语义 | 本次适用的认证授权、资源归属、重复/幂等、分页、重试和外部访问条件有明确语义，区分客户端行为与提供方保证；不自行添加机制或以客户端检查替代服务端授权 | 按角色、资源及重复/边界场景走查访问条件和副作用，核对分页/重试等适用规则的来源；外部服务以其实际版本契约核实，不猜保证 |
| E2.3 | 契约一致 | 接口与有效需求、数据和协作契约一致，权威来源、版本及兼容影响明确；已有机器契约执行适用验证并核对派生说明，不能以文档一致或 Mock 自洽证明真实提供方符合契约 | 检查权威定义、实现/消费方和示例的版本一致性，按项目运行适用 Schema/契约检查；区分静态校验、替身及真实边界证据，审阅兼容变化和确认来源 |
