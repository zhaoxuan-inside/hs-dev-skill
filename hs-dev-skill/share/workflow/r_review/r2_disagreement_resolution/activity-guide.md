# R2 分歧与异议处理

## 目的与适用范围

把团队（人或 Agent）之间对决策、契约或实现行为的分歧变成可裁决、可追溯的事项。适用场景：评审中双方依据不同的结论、对有效决策的异议、两份文档/代码互相矛盾且各有来源。单纯缺信息先回负责活动补齐，不作为分歧登记。

## 输入与输出

输入为登记的异议对象（决策 ID、内核 ID、代码单元或文档单元）、各方依据及期望结果。输出逐条裁决（证据复核结论 / 新决策记录 / 移交执行）、回写后的登记状态及仍未决异议的阻断范围。

## 工作与核验

1. 每条异议绑定可定位对象 ID 与其内容摘要，写明依据与期望结果；同一对象的重复异议合并引用。
2. 按类型分流：事实分歧以证据复核（运行结果、源码、登记摘要）裁决；取舍分歧升级为 decision-record（记录被否方案）并按需 supersede 旧决策；执行分歧（怎么改）移交负责活动并注明约束。无裁决路径的异议保持显式未决。
3. 裁决后沿 ID 链回写受影响契约内核与文档；受影响确认按统一机制失效，未决异议使相关验收保持阻断并在验收视图中可见。
4. 受影响方（任务、活动或人员）通过决策台账与任务材料获知变更；不要求广播通知，但回写必须完整。

## 边界与交接

本活动不代替用户做产品取舍（需要用户决定时按当前模式请求确认），不修改实现代码。事实类结论交还负责活动执行；未决异议的数量与范围如实呈现，不静默消失。
