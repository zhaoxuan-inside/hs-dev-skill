# F3 上下文装配

## 目的与适用范围

为本次当前任务取得安全、版本有效且足够工作的最小上下文。具体请求与结果以[语义上下文协议](../../../context/context-protocol.md)为准，不另建读取接口或复制完整历史。已有足够且仍有效的上下文直接复用，不为进入活动重新加载全部正文。

## 输入与输出

输入为当前任务目标、有效决定、必要契约和通过标准，以及目标对象/依赖定位和可核实持有内容。输出是协议核验的工作集及来源、版本、覆盖和预算信息；缺失时交付具体缺口，不把不完整内容说成已就绪。无需新建上下文报告或常驻副本。

## 工作与核验

1. 从当前对象及实际缺口列出必要内容，必要选择器标 required，按适用章节/符号等定位；区分必要依赖和可选参考，不递归读取全部上游、未来切片或恢复历史。
2. 按主入口检查安全读取条件，通过现有 context 机制取得内容。索引是定位派生物，不能以缓存或目录标题替代实际契约；不因读取错误自动修复索引或初始化工程。
3. 使用实际仍可见且版本匹配的 held 清单选择 delta；新会话或压缩后清空或重新核实持有内容，不能推定模型仍记得。单元身份不等于内容版本，必要依赖闭包由协议检查。
4. 消费正文前核对 status、coverage、units、missing/deferred 及版本，只有 complete 才作为完整上下文；可选延迟项按当前缺口再取，完整性不代表业务验收通过。
5. 歧义时明确选择对象，缺失时核实具体源或依赖，版本漂移时丢弃失配结果。预算不足时缩小非必要范围、改为独立任务或按协议处理，不能去掉真实必要约束、截断原子单元或用自写摘要冒充完整材料。
6. 核对实际预算口径，字节估算不等于精确 token 限制；不重复实现协议计数或临时下载 tokenizer。记录必要集合是否满足及未解决条件，按当前模式处理适用确认后交回任务执行。

## 边界与交接

本活动只装配当前工作所需内容，不自动重构源文档、增加索引或改写业务决定；大章节调整等维护工作须有对应授权。关键内容缺失时保持依赖阻断，其他独立工作可继续。装配成功不证明任务实现、测试或验收完成，不自动进入写入、恢复或发布。
