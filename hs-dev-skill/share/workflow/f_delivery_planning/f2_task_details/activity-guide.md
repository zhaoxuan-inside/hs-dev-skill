# F2 任务详细设计

## 目的与适用范围

把本次选定切片细化为可执行、可验证的当前任务。已有任务有效时更新而不重建同义任务；后续任务保留定位引用，不提前装入全部实施正文或按每个私有方法创建任务。

## 输入与输出

输入为有效切片和设计、实际依赖、相关代码及已有任务/工作区状态。输出形成最小任务契约：目标与范围、有效输入、影响对象、执行检查、验证方法及完成条件、依赖、恢复要求和未决项。简单任务可沿用现有记录，不强制另建详细设计文档。

## 工作与核验

1. 核对任务目的、边界和有效上游，检查已有任务是否已覆盖本次工作；缺失的产品或技术决定返回负责活动，不在任务步骤中悄悄补规则。
2. 根据实际调用和修改边界定位适用接口、方法、数据、配置、文档及测试，关联已有符号；新对象标明拟定，不猜文件路径或签名冒充现状，不把对象列表扩大为全项目清单。
3. 按可验证结果组织必要执行步骤，交代输入、预期产物及副作用边界；步骤足以实施即可，不镜像每行代码或规定无依据的抽象。专业细节复用领域技能。
4. 与 testing 核对检查项、预期、命令或人工操作及环境条件，说明直接或调用链验证和未覆盖边界；方法列表不等于测试覆盖，验证计划不记已通过。低影响变更不为凑清单强制新增测试。
5. 沿实际依赖核对前置产物、证据和版本，检查当前任务状态与已有修改。可规划独立任务，但实际创建/继续受管任务仍服从系统门禁；中断、漂移或门禁拒绝交 continuity，不伪造完成或直接新建任务逃避恢复。
6. 说明必要恢复范围及不可逆限制，实际快照由执行协议落实；审阅任务可执行性、完成条件及阻断，展示结果并按当前模式确认。

## 边界与交接

关键依赖或契约未定时当前任务不能称就绪，独立规划工作可继续而不绕过安全限制。计划不自动授权业务修改、恢复、并行写入或发布。适用标准与确认满足后按缺口转上下文/恢复准备或实施，不以任务已登记、步骤齐全或命令存在宣称功能已完成。
