# 可选摘要追踪协议

本协议定义事件、存储和解释边界；执行与查询方法见[追踪技能](../../skills/hs-dev-trace/SKILL.md)。trace 提供尽力记录的诊断线索，不承担业务审计完整性、恢复或验收责任。

## 开关与作用域

trace 独立于 mute、activity、stage，默认关闭。持久设置由实际解析的 `trace.enabled` 决定，全局 `--trace` 临时开启当前调用，不保存配置，也不改变确认模式。banner 和 JSON meta 展示当前开关，配置来源由配置解析结果核实。

关闭时不因事件记录创建目录或文件，但已有日志不会因此删除，仍可查询。开启后按工程根隔离记录于 `hs-dev-skill/trace/`；不跨项目汇总，不申请业务修改 UUID，不改变业务源或索引。开启不是重放历史，未记录的业务动作不得为补事件自动重做。

## 事件内容

事件包含 `event_id`、`run_id`、`timestamp`、`event`、操作关联、丢弃计数观察值及 `attributes`。只有实际有操作凭据时才有对应顶层操作标识，不能假设所有事件都属于业务修改。运行、任务、活动及操作标识按实际字段关联，不混用。

摘要属性只接受实现白名单中的标量字段，涵盖名称、结果、原因代码、耗时、上下文数量/字节数、缓存命中和路由等；没有实际采集的字段不得推定存在。当前实现限制事件名长度及属性字符串长度，序列化事件还受字节预算约束；截断不是脱敏，也不保证摘要足够解释完整业务过程。

### 阶段、活动和上下文统计

`stage` 和 `activity` 事件按 `task_id`、`stage_id`、`activity_id` 关联，记录 `outcome`、累计 `duration_ms`、`retry_count`、`context_chars` 和 `source_count`。统计范围为任务实际选择且观测到的阶段/活动，不为未执行活动伪造耗时。

- 任务开始时进入首个活动；通过工作流进入其他活动时结束前一活动的当前区间，跨阶段时同时结束前一阶段区间。再次进入累计新的区间。同一活动重复进入不重置起点。
- 审批成功结束对应活动；该阶段在本任务内选择的全部活动获批后结束阶段。任务完成或回滚结束仍在进行的区间。事件结果包含 `entered`、`left`、`check`、`context`、`completed` 及任务终态。
- 耗时是记录器观察到的进入至离开/结束的墙钟时间，包含人工等待、工具等待和进程之间的间隔，不代表 CPU 或模型推理耗时。阶段耗时独立计时，不将阶段内活动耗时机械相加。系统时钟倒退时负区间按零处理。
- 重试定义为同一任务、活动、检查项的上次已记录结果为 `FAIL` 时，再次提交该项结果；首轮失败不算重试，不同检查项不相互影响。工具内部重试、未接入的模型重试与审批返工次数不在此计数内。
- `context_chars` 是 ContextProvider 实际交付的 `body[].text` 的 Python Unicode 字符数之和，包含正文内换行，不含响应 JSON 元数据；多次交付累加。delta 已持有而未交付的内容不重复计入；空正文为零。`source_count` 为累计交付片段数，并非去重文件数。

每次上下文交付记录带 `context_id` 的 `context` 摘要（字符数、片段数、输出字节数和本次生成耗时），每个交付片段单独记录 `context_source`：完整项目相对路径 `source_path`、`start_line`、`end_line` 和片段字符数。路径不按普通摘要字符串的 160 字符上限截断；单事件超预算时仍丢弃并计数。用同一 `context_id` 关联摘要及来源，用任务/阶段/活动标识查看归属；不保存正文。没有 task_id 的上下文仍记录来源，但不归入阶段/活动。通过其他工具直接读取的上下文没有被本记录器采集。

跨进程统计保存在 `trace/metrics/<task_id>.json`，不修改业务任务数据，不进入索引、恢复快照或模型上下文。该旁路状态按 `max_age_hours` 在写入时过期清理，最多保留 `max_files` 个任务计数文件，与日志轮换分别执行。被淘汰后重新从观测起点计数，不重建历史；它只支持尽力记录，不保证完整统计。关闭期间不更新统计；若随后重新启用，已有开放区间的墙钟时间可能跨越关闭时段，不能当作连续采集证据。

禁止记录凭据、完整对话、代码、文档正文及不必要的用户数据，即使放在白名单字段内也不例外。生产者负责提供安全摘要，不能把任意异常正文或请求载荷塞入 reason/name 等字段。

### 任务执行链路图

开启追踪后，任务关联事件在写入日志时保存明确的边标识，跨 CLI 进程延续同一任务的记录链：

| 顶层字段 | 图中的关系 | 含义 |
|---|---|---|
| `previous_event_id` | `next` | 同一任务上一条已写入的事件；表示记录先后，不代表业务依赖或并行执行的因果关系 |
| `parent_event_id` | `contains` | 阶段归属任务观测根，活动归属阶段，上下文及检查归属活动，来源片段归属该次上下文交付 |
| `retry_of_event_id` | `retry` | 同一活动、同一检查项上次已记录的失败事件与本次再次执行的关系 |

图中保留实际事件节点而非仅合并阶段名称，因此能够展示重复进入、回到较早活动、失败及后续重试。节点保留事件时间、run/operation 标识及已有摘要（耗时、重试数、字符数、来源路径等）。有明确任务标识的 CLI 命令、操作获取及工作区迁移也进入该任务链；没有任务归属的意图分类等事件不猜测关联。阶段或活动尚未观测到进入事件时，事件只能关联到已有的观测祖先，不补造开始节点。

关联游标保存于 `trace/links.json`，与事件写入共用独占写锁；按 `max_age_hours` 过期，最多保留 `max_files` 个任务的游标。首次开启、游标淘汰、关闭期间未记录或异常中断会造成观测链缺口。游标不是业务或恢复状态；图的节点和边以日志中的事件字段为准，不依赖游标文件重建历史。

查看结构化图：

```bash
python3 hs-dev-skill/scripts/hs_dev.py --root . --output json trace-graph --task-id TASK_ID
```

查看可渲染或复制保存的 Mermaid 图：

```bash
python3 hs-dev-skill/scripts/hs_dev.py --root . trace-graph --task-id TASK_ID --format mermaid
```

`trace-graph` 为只读查询，独立读取当前保留日志，不受 `trace-query` 的 100 条上限影响。默认最多返回最后 1000 个匹配事件，`--limit` 范围为 1～5000；节点顺序按日志轮换次序和文件内写入次序排列，不按墙钟时间猜测。返回 `nodes`、`edges`、`missing_event_ids`、`truncated`、`unlinked_event_ids`；Mermaid 使用 `next`、`contains`、`retry` 标注连线，悬空引用显示 `unavailable event`。旧日志没有关系字段时只显示已知节点，并在 `unlinked_event_ids` 中列出，不按时间或活动名补线。

`coverage` 固定为 `retained_events_only`，`history_complete` 固定为 `false`。`truncated=false` 仅表示本次图查询未因节点上限裁剪，不能证明未轮换、未丢弃或完整记录了任务。查询失败显式报错。图按需生成，不自动导出文件或复制完整日志。

## 容量、轮换与失败

| 配置 | 含义与当前默认值 |
|---|---|
| `max_file_bytes` | 单文件轮换预算，默认 1,000,000 字节 |
| `max_files` | 保留文件数量预算，默认 5 |
| `max_event_bytes` | 单事件序列化字节预算，默认 4096，不得超过文件预算 |
| `max_age_hours` | 文件过期窗口，默认 48 小时 |

以实际解析配置为准，预算须为正。当前记录器在写入时按文件修改时间处理过期文件，再按文件大小轮换；不是定时清理，也不是逐事件精确保留到期时间。查询不会主动淘汰过期文件，不能把该窗口当作事件一定存在或一定已被删除的保证。

写入使用项目内独占写锁；锁冲突、超预算或记录错误可导致事件丢弃，不能阻断业务结果。丢弃计数保存在当前进程内，事件可携带当时观察值；新进程查询的计数不代表所有历史损失，不能由零推断没有丢事件。查询错误须显式报告，不能伪装成空结果或业务失败；不手工删锁、篡改事件或重放业务来补记录。

## 查询与结论

`trace-query` 支持 run、task、operation、stage、activity、context、event、outcome 和起止时间过滤（新增 `--stage-id`、`--context-id`），默认返回上限 20，可选范围 1～100。时间使用可解析的 ISO 8601，调用方应提供时区，起始不得晚于结束。先以具体标识缩小范围，仅为明确缺口放宽。

返回结果是受限制的样本，不提供完整总量、全局时间倒序或分页遍历承诺；当前按文件修改时间选文件，再按文件行顺序读取。需要时间比较时可以对已取得样本排序，不能将其称为全部最新事件。

空结果可能由关闭、条件未命中、轮换、过期或事件丢弃造成，不能证明业务未发生。记录了请求、路由或命令结果也不等于业务最终成功；结论需由实际状态、代码或测试证据支持。

## 数据与责任边界

trace 不作为恢复日志、验收证据或人工确认记录，不进入业务索引、快照或默认模型上下文。诊断仅提供必要的过滤摘要及其条件、局限，不自动复制完整日志、导出或持久开启。

记录功能正常、查询得到样本、业务正确及人工验收分别判断。未执行追踪验证不能宣称追踪链路完整；关闭追踪或追踪失败不能撤销有效业务成果，也不能减免正常验证和确认责任。
