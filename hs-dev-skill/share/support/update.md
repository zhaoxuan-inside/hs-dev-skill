# 完整包安装更新协议

本协议定义源包、目标和替换不变量；执行清单见[更新技能](../../skills/hs-dev-update/SKILL.md)。实际 CLI 子命令为 `install --source <完整包目录> --target <安装目录>`，不是 update；`--root` 不表示安装目标。

## 授权与范围

实际安装须有对目标和替换动作的明确授权，已有有效授权直接沿用；检查版本或评估可行性不等于授权替换。缺少必要路径或存在影响替换范围的歧义时先核实，不猜安装目录，宿主文件系统权限仍须满足。

本入口只安装内部校验通过的当前格式完整包，不自动下载、查找最新发布、解析旧版、迁移格式或合并零散文件。内部包校验只证明实现检查的结构与一致性，不是来源真实性、安全审计或全部功能验证。

## 源包与目标约束

- 源包须有可核验的实际路径、版本来源和完整包校验结果；文件名或版本字符串不能替代校验。仅提供部分文件时不得宣称可完整安装。
- 源与目标必须独立，不能相同或互为父子目录。工作副本和符号链接不作为安装目标；调用方核实路径及其实际位置，不以解析后路径掩盖不合适的原始目标。
- 目标应是预期的独立安装目录，不能混入工程产物、用户数据或其他未授权内容。安装是整目录替换，不是合并：目标中源包不含的本地文件不会保留。发现定制或归属不明内容时先处理范围，不直接覆盖。
- 使用已核实、不会在替换中失效的 CLI 入口；调用方避免和其他安装或目标写入并发，不假设安装器提供跨进程协调锁或读者无感切换。

## 替换与验证

安装器先校验源包，在目标父目录创建临时区，复制并校验暂存包；存在旧目标时先移入临时备份，再将暂存包移至目标，并重新执行包校验。复制遵循安装器的排除规则，不应以复制源工作区的缓存或构建产物代替完整包安装。

替换由多个文件系统步骤组成，不承诺跨步骤的整体原子性或并发读者始终可用。源包在校验和复制期间应保持稳定，调用方不能一边生成源包一边安装；目标父目录需具备创建临时区和重命名等实际权限。遇到权限或路径错误不得以手工删除旧目录绕过。

成功须核对实际目标、安装后包校验及版本，按任务需要追加不修改工程的最小启动或帮助检查。结果只支持实际执行的验证范围，不以结构校验通过证明全部技能、运行依赖或业务功能可用。

## 失败与恢复

替换过程出错时，安装器尝试删除失败的新目标并恢复临时备份；原先不存在目标时不存在“恢复旧版本”。失败处理也可能失败，调用方必须核实实际目标与更新前基线是否一致，不能仅因有异常处理代码就报告恢复成功。

失败或中断后保留原始错误，说明目标存在性、可用性、已核实范围及缺失条件。恢复未证实或残留状态不明时停止后续覆盖，不自动重装、清理或扩大回退范围。普通异常恢复不等于对强制终止、断电等情况有持久恢复保证。

临时备份仅用于本次替换过程，临时区清理后不提供长期回退能力。需要长期保留旧安装时，应在已授权范围内先明确独立保存位置和验证方式；不得承诺成功更新后仍可从临时备份回退，也不将业务恢复快照视为安装目录的当然备份。

## 结果与责任边界

结果记录源包、目标、版本、替换范围、命令结果、实际验证及未验证项；失败时另记录旧目标是否已核实恢复。区分仅检查、未执行、安装成功且已校验、失败且已核实恢复、失败且状态待核实，不把未执行或恢复不明记为成功。

安装不改工程产物、任务验收或 Agent 配置，不自动同步其他安装、Git 提交、push、发布或数据迁移。凭据及不必要的用户数据不进入日志或报告；简单安装直接回复，不强制新建文档。后续动作按其实际授权及负责过程处理。
