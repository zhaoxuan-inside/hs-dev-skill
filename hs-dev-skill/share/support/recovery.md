# 快照与恢复协议

本协议定义恢复数据及安全不变量；命令选择和执行清单见[恢复技能](../../skills/hs-dev-recovery/SKILL.md)，操作凭据与发布遵循[执行协议](../core/execution.md)。任务上下文续做由 continuity 组织，文件恢复不等于任务完成。

## 恢复依据

- 快照保存受管文件前像及目录信息，包含恢复所需的代码、配置与运行状态；范围以实际 manifest 为准，不承诺覆盖工程外部资源、数据库或未纳管文件。
- 对象按 SHA-256 寻址、去重并校验；manifest 关联 snapshot_id、task_id、创建时间、文件摘要及元数据。缺失、损坏或过期的数据不得作为有效恢复点。
- 操作记录及 changelog 保存修改集合、顺序、后像、状态与快照关联；失败或中断操作仍需保留可恢复依据。快照和日志不能单独替代对实际当前内容的核验。
- 新任务、重大或大量修改前按执行机制建立恢复点；已有自动快照不重复创建。只读分析不产生快照，恢复正文与历史不进入默认模型上下文。

## 恢复范围与冲突

| 恢复类型 | 约束 |
|---|---|
| 操作级回滚 | 依据操作实际修改集合及记录后像检查当前内容；存在后续编辑冲突时拒绝覆盖。写入与日志之间中断造成的未知不能猜测为可安全回滚 |
| 任务级回滚 | 恢复整个任务基线，可能覆盖基线后新增、删除及修改；CLI 拒绝存在后续任务的情况，但这不证明没有后续手工编辑。执行前必须核对当前差异、归属与授权，不作为操作级冲突拒绝后的兜底 |
| 中断所有者撤销 | 使旧凭据失效，不恢复文件、不自动解除内容漂移；后续仍须按状态执行核验、reconcile 或回滚 |
| 接受现有修改 | reconcile 核验并发布授权范围内的实际修改，不是恢复前像；不能以接受新基线掩盖未解释变化 |

恢复只覆盖明确授权及可证明归属的范围，保护无关和后续修改。冲突、归属不明、快照不可用或恢复集合不完整时保持阻断，不能手工删日志、改状态或绕过协调入口调用底层 restore。普通“继续”和进程超时不构成回滚授权。

## 恢复后核验

恢复须核验目标文件摘要及适用的新增、删除、移动、目录与元数据结果，并核对操作/任务状态、源内容和索引发布的一致性。按实际影响补充必要行为验证；旧测试和确认仅在其内容及依赖仍有效时复用，按[验收协议](../core/acceptance.md)处理相关失效。

命令成功、文件内容恢复、工作区安全及业务行为正确分别判断。仅协调模块完成所需核验后才可恢复安全状态；恢复命令失败或中断时保留错误和恢复依据，不自动开始下一次业务修改。

结果应包含对象与范围、快照/操作标识、实际恢复结论、检查证据、冲突及未验证项；未执行或仅撤销凭据不能记录为恢复成功。恢复不代签人工确认，不自动 Git 提交、push 或部署。

## 保留与清理

实际保留参数来自配置；默认任务与快照数量上限各为 5、时间窗口为 48 小时，配置可收紧，不能超过实现允许上限。未受保护记录超过时间窗口或数量预算时可淘汰；不是必须同时满足两个条件。活动任务及在用操作引用的快照受保护，可能暂时超过数量预算，不为凑上限删除在用依据。

清理由现有 retention 机制处理：先处理过期记录及引用可恢复性，再只回收无存活引用的对象。恢复点淘汰后相关记录应明确不可恢复，不能留下仍可恢复的错误承诺；未完成任务即使被淘汰仍保留阻断，不自动完成。不因读取本协议自动清理，也不手工删除对象或 manifest 绕过引用保护。
