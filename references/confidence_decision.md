# 置信度决策协议（设计多问 / 实现少问）

**何时读**：存在尚未拍板的选择点，或进入/切换 `work_mode` 时；每会话最多一次。

目标：**设计阶段逼出真实需求，实现阶段少打扰、不瞎猜**。通用工程惯例直接落地；产品特有空白在设计期问清并冻结；实现期禁止用「少问」掩盖未决产品语义。

与 [right_sizing](right_sizing.md) 配套：先写 `change_size` 与 `work_mode`。  
与 [learn_and_prefer](learn_and_prefer.md) 配套：学习/偏好抬高实现期置信。  
与 [load_latch](load_latch.md) 配套：未过装载门闩禁止「先开干再决定问不问」。  
与生命周期**产品需求冻结**配套：M/L 阶段 0 未闭合前不得进选型/满配详设。

---

## 0. 双轨：先定 `work_mode`

每个选择点落盘或编码前，先判定并写入 brief / context_pack / 任务元数据：

| `work_mode` | 何时取 | 询问策略 |
|---|---|---|
| **DESIGN** | M/L 阶段 0～3；写/改 PRD、ADR、架构、接口/UI 详设；用户要澄清/对齐/选型；需求模糊或产品语义未冻 | **多问**：走 §1 设计澄清轨 |
| **IMPLEMENT** | 阶段 4～6；S 轻量对齐后的编码；明确「按已冻结设计实现」；局部 bugfix/文案/样式且不改产品语义 | **少问**：走 §2 实现闸门轨 |

**默认**：`change_size=S` 且 DoD 已清 → `IMPLEMENT`；`M|L` 且冻结未过 → `DESIGN`；不确定 → `DESIGN`（宁可多问一轮）。  
**切换**：冻结门禁通过后切 `IMPLEMENT`；实现中暴露产品未决 → **回切 DESIGN**（可迷你回合），禁止在 IMPLEMENT 里静默猜业务。

用户可随时说「跳过澄清 / 直接做」→ 结束 DESIGN 轨：用一行记下重大默认假设，再进 IMPLEMENT。

---

## 1. DESIGN 轨（多问 · 设计树澄清）

适用：产品语义、验收口径、交互主路径、限界上下文、对外契约、持久化业务字段、不可逆策略、模糊 UI 方向等**尚未闭合**的决策。

### 1.1 原则

1. **事实自查、决策问人**：可用工具/代码/资料查到的，禁止问用户；选项与取舍必须问。
2. **设计树 + 前沿轮询**：每个决策是树节点；**前沿** = 前置已定、现在可问的节点。每轮只问前沿（建议 2～5 题），等答复再展开下一轮。
3. **带推荐答案**：每题给推荐选项，措辞上「yes/好」即可采纳推荐，降低负担。
4. **可跳过**：首条消息可附一句「若要跳过澄清直接开干请说」；用户跳过后记假设，不再空转追问。
5. **一轮可多题，但禁止问卷灌水**：不把通用工程项、已对标收敛项、偏好已命中项塞进问卷。
6. **闭合才冻结**：核心场景 / DoD / 影响架构的产品约束齐且无冲突 → 写冻结结论 → 允许切 IMPLEMENT。

### 1.2 每轮格式（强制）

```text
❓ **Q1** - **<题目标题>**: <题干；可含 2～3 选项>

➡️ 推荐：<选项与一句话理由>

---
（同轮其余题…）
```

答复后：更新 PRD/设计/词典；同步全局 `preferences.yaml`（产品偏好）；重算前沿；前沿空且冻结条件满足 → 宣布 `work_mode=IMPLEMENT`。

### 1.3 设计期必扫领地（非逐条朗读，缺则入前沿）

- 这是什么、为谁、成功/失败长什么样（含反目标）
- 核心场景与 DoD；非目标
- 权限/计费/归属等业务特有规则（资料未给则必问）
- 对外契约与数据持久化形状是否影响多端/迁移
- 模糊 UI：先 GitHub ≥2 对标摘要，再问方向性取舍（不是问像素）
- 与既有 PRD/词典冲突时的裁决

### 1.4 设计期禁止

- 用「常见做法」填补会影响选型/架构的产品空白后强行冻结  
- 未问清就写死不可逆 schema/公开 API  
- 把实现细节（文件路径、函数名）当澄清题（除非原型片段比散文更准）

## 2. IMPLEMENT 轨（少问 · 四条件闸门）

适用：设计已冻结或 S 路径轻量 DoD 已写清；正在拆任务、写代码、补测、跑门禁。

### 2.1 决策前检查（强制顺序）

1. **检索既有资料**：会话、已冻 PRD/ADR/详设、词典、context_pack、相关代码；全局 `preferences.yaml` / `tech_learning/`（先 `global_index_db search`）；项目 `_01_dev_rule/`。  
2. **偏好命中则停问**。  
3. **新技术 / 模糊技术点**：先 `learn_and_prefer` 学习/对标，再估置信。  
4. **判定是否通用解**（行业默认、Skill 强制规范、可继承 ADR）。  
5. **自评置信**（0–100）与首选/次选差距。  
6. **套用 §2.2 闸门**：不满足 → 禁止提问、自主决策并落盘；满足 → 禁止猜测、结构化询问（可临时 `BLOCKED`）。

### 2.2 询问闸门（须同时为真才问）

| # | 条件 | 说明 |
|---|---|---|
| A | **影响面广** | 显著改变对外契约、持久化形态、跨模块边界、核心业务语义、不可逆迁移或长期运维成本 |
| B | **项目特有** | 取决于本产品业务/组织约束，非通用工程惯例 |
| C | **资料未提及** | 会话 + 全局偏好 + `hs_dev_docs` + 代码均无倾向 |
| D | **置信接近** | ≥2 可行选项且最高与次高差距 **≤15** |

**实现期额外硬规则**：

- 已在 DESIGN 冻结的结论 → **禁止再问**（除非用户推翻或发现冲突，则回切 DESIGN）。  
- 局部命名、单测夹具、注释、与对外行为无关的内部拆分 → **永不问**。  
- 通用解（REST 复数路径、指数退避、既有 JSON 风格等）→ **永不问**。

### 2.3 置信标定

| 区间 | 默认动作 |
|---|---|
| ≥80 | 自主决策 |
| 65–79 | 自主；设计/ADR 中一句假设 |
| 50–64 | 同时满足 A+B+C 且差距≤15 → 问；否则取最高并注明假设 |
| <50 | 先学习/对标；仍不足且 A+B+C → 必须问或回切 DESIGN；影响面窄 → 可逆默认 |

### 2.4 询问时行为（实现期触发）

1. 停在决策点；任务则 `status --set BLOCKED`。  
2. 一次只抛真正卡点（结构化：决策点 / 2～3 选项+利弊+置信 / 影响面 / 资料缺口）。  
3. 答复写入对应文档 + 全局偏好；解除 BLOCKED；**立即继续**，禁止空等「请继续」。

---

## 3. 与各阶段的衔接

| 阶段 | 默认 mode | 典型行为 |
|---|---|---|
| 0 需求 | DESIGN | 设计树澄清 → 冻结；用户跳过则记假设 |
| 1～3 | DESIGN | 选型/架构/详设分叉：产品向用设计轨；纯工程向可短问或自决 |
| 4～6 | IMPLEMENT | 四条件闸门；新暴露产品空白 → 回切 DESIGN |
| S 快路径 | IMPLEMENT | 轻量 DoD 后少问；若发现改到产品语义 → 升 M/L 并 DESIGN |

**合法停点**：DESIGN 前沿等待答复、实现期 §2.2 询问、（M/L）冻结未过、外部 `BLOCKED`。除此之外持续推进至门禁+归档+本地 Commit。
