# 项目类型与清单组织规范（Project Types & Checklist Structure）

**何时读**：阶段 0 分级后确定项目类型时；编写任意步骤的工作清单/验收清单/产出文档时；类型判定模糊或跨类型组合时；每会话最多一次。

**分工**：分级与意图 → [`right_sizing.md`](right_sizing.md) / [`intent_routing_and_gates.md`](intent_routing_and_gates.md)；阶段细则（三件套落点）→ [`spec_driven_lifecycle.md`](spec_driven_lifecycle.md)。

---

## 0. 三件套与清单组织规范（核心原则）

**每个开发步骤 = 三件套**：

| # | 组件 | 作用 | 不达标怎么办 |
|---|---|---|---|
| 1 | **工作清单** | 记录本步骤"要做什么"（原子动作） | — |
| 2 | **验收清单** | 记录"做到什么程度才达标"（逐条可查） | **继续问答或继续开发**，禁止带病进入下一步 |
| 3 | **产出文档** | 本步骤交付物（路径清单） | 缺即未完成 |

**清单组织规范（树状 · 原子叶子）**：
- 三个清单统一用**树状层级**组织；
- **叶子 = 原子独立项**：一项只含一个可判定内容，**禁止合并**（如"幂等/补偿/fallback 100% 覆盖"必须拆成三个叶子）；
- **父节点仅做分组**，不承担判定；判定只发生在叶子；
- 每个叶子必须**可独立验证**（机器可查，或人工可查）。

**通用性**：工作清单与验收清单**按项目类型参数化**——基础清单（全类型通用）+ 类型专属清单（各类型差异）；单个项目只做"套用 + 裁剪 + 记录差异"，不从零定制。

## 1. 项目类型判定（P1 ~ P6）

| 类型 | 定义 | 触发条件 | 代码收敛位置 |
|---|---|---|---|
| **P1 纯后端服务** | 无 UI，仅提供服务端能力（API/消息/批处理/微服务） | 无 `frontend/`、无 `apps/*` | `backend/`（微服务 `services/`） |
| **P2 Web 应用** | 含响应式浏览器前端 + 后端 | 存在前端页面且浏览器内运行 | `backend/` + `frontend/`（或单工程） |
| **P3 桌面客户端** | 桌面应用（本地窗口 + 打包分发） | 存在桌面窗口应用 | `apps/desktop/` |
| **P4 移动客户端** | 移动 App / H5 / 小程序（触控优先） | 存在移动端分发 | `apps/mobile/`（可细分 `ios/`、`android/`） |
| **P5 全端组合** | 多端并存，共享契约 | **≥2 端并存** | `apps/*` + `packages/` |
| **P6 纯库/包/CLI 工具** | 无部署，被外部引用 | 交付物是包/SDK/CLI，非可部署服务 | `packages/` 或独立仓库 |

---

## 2. 组合规则

1. **P5 全端** = P1 ∪ P2 ∪ P3 ∪ P4 各端专属验收**全量叠加** + P5 专属（共享契约层 + 跨端一致性）；叠加按"类型卡整体并入"，不写合并检查项。
2. **P6 带 demo**：库内含可运行 demo 页面 → **叠加 P2**（demo 走 Web 验收）。
3. **多类型叠加**：验收清单 = 基础清单 + 各类型专属清单**并集**；叶子仍保持原子独立。
4. **类型变更**：实现中发现类型判定变化（如新增端）→ 回切 DESIGN，重判类型并重跑受影响验收，禁止静默沿用旧类型。

## 3. 类型卡片

### P1 纯后端服务

**定义**：无任何 UI，仅提供服务端能力——HTTP/gRPC API、消息消费、批处理/定时任务、微服务。

**典型项目**：订单/支付 API、数据同步管道、网关、消息消费者。

**代码结构**：`backend/`（微服务则 `services/`）；无 `frontend/`、无 `apps/*`。

**影响的关键阶段**：
- 阶段 0：**豁免**原型与设计语言（PRD 注明"无 UI，豁免"一行）；仍须审讯业务语义/对外契约/DB 形状
- 阶段 1：语言 / 存储 / 中间件 / 协议选型
- 阶段 2：分层 / 微服务边界 / 限流熔断
- 阶段 3：四要素全量（DB + API + 六元组 + 调用链）
- 阶段 5：方法级 ≥85%、补偿/降级 100%、契约测试；E2E 可无浏览器

**专属验收维度**：

```
契约与迁移
├── [ ] API 请求/响应字段与 Mock Schema 严格一致
├── [ ] 前向迁移脚本 V 存在且可执行
├── [ ] 回滚脚本 U 存在且与 V 原子配对
└── [ ] 迁移回滚已验证通过

异常与补偿路径
├── [ ] 幂等分支用例存在且通过（唯一键/业务操作 ID）
├── [ ] 补偿分支用例存在且通过（_compensate）
├── [ ] fallback 分支用例存在且通过（_fallback）
└── [ ] 超时重试指数退避用例存在且通过

安全
├── [ ] SQL/NoSQL 注入用例通过
├── [ ] 垂直越权用例通过
├── [ ] 水平越权用例通过
└── [ ] 敏感字段日志脱敏用例通过

性能
├── [ ] 核心接口 P99 无劣化（对照基准）
└── [ ] QPS 达基准线

无 UI 豁免
└── [ ] PRD 存在"无 UI，豁免原型"声明
```

**边界**：与 **P6**——P1 是可运行可部署的服务，P6 是被引用的包/SDK。与 **P2**——P1 无 `frontend/`、无原型产物。

### P2 Web 应用

**定义**：含响应式浏览器前端的完整应用（前端 + 后端，或前后端一体）；有 UI → 原型必产。

**典型项目**：SaaS 管理台、电商前台+后台、内容平台、企业内部系统。

**代码结构**：`backend/` + `frontend/`（或单工程）；无 `apps/desktop`、无 `apps/mobile`。

**影响的关键阶段**：
- 阶段 0：必产双轨原型 + 可交互 HTML 预览（多端视口 + 四态）；根目录 `DESIGN.md`；UX 四定律/组件六态；业务语义签收 + 冻结确认单（含视觉签收）
- 阶段 1：前端框架/构建/CSS 方案 + 后端选型
- 阶段 2：前端模块结构（FSD/按业务边界对齐）+ 后端分层
- 阶段 3：四要素 + 前端方法设计（ALGO/TRANSFORM/GUARD/STATE/ORCHESTRATE/ADAPTER）
- 阶段 5：前后端分离测试、组件测试
- 阶段 6：DevTools 运行态 / a11y / CWV 门禁

**专属验收维度**：

```
原型与设计语言
├── [ ] 双轨原型存在（Mermaid 拓扑）
├── [ ] ASCII 比例线框存在（含字阶/间距/Tokens 标注）
├── [ ] 单文件 HTML 原型存在且双击可直读
├── [ ] HTML 原型含 1440/768/390 视口切换
├── [ ] HTML 原型覆盖四态（Empty/Loading/Populated/Error）
├── [ ] 根目录 DESIGN.md 存在（具象参照物 + Tokens + Anti-Slop）
└── [ ] 特性 PRD/vibe_spec 声明 Inherits: /DESIGN.md

视觉签收（阶段 0 冻结前提）
├── [ ] 页面最大容器尺寸与栅格比例明确
├── [ ] 标题/正文/标签字阶均有清晰标注
├── [ ] 数值/金额列标明 tabular-nums
├── [ ] 间距步进与 Design Tokens 一致
├── [ ] 响应式断点（宽/窄屏）流转自然
├── [ ] 页面四态无死角
├── [ ] 布局可映射为组件树
└── [ ] 颜色/间距可映射为 CSS Variables/Tailwind 类

前端运行态质量（阶段 6）
├── [ ] 无未捕获 Console 报错
├── [ ] 无网络请求挂起/死锁
├── [ ] LCP ≤ 2.5s
├── [ ] 路由切换后无游离 DOM
├── [ ] 路由切换后无残留事件监听器
├── [ ] 键盘导航全路径闭环
├── [ ] WCAG 对比度 ≥ 4.5:1
└── [ ] ARIA 属性合法性通过

前后端契约
├── [ ] 前端调用字段与后端 API Schema 一致（契约测试）
└── [ ] Mock Profile 与真实环境双轨 E2E 均通过
```

### P3 桌面客户端

**定义**：桌面应用（本地窗口 + 打包分发），有 UI → 原型必产（桌面多窗格形态）。

**典型项目**：桌面效率工具、企业工作台客户端、本地数据处理桌面端。

**代码结构**：`apps/desktop/`；跨端共享契约进 `packages/`。

**影响的关键阶段**：
- 阶段 0：原型必产（多窗格布局、快捷键、右键菜单、窗口缩放）；`DESIGN.md`；视觉签收含桌面交互检查点
- 阶段 1：桌面框架（Electron/Tauri/Qt/原生）、打包与分发方案、自动更新
- 阶段 2：进程模型（主/渲染进程）、模块边界
- 阶段 3：本地存储、IPC/进程通信、六元组（含本地方法）
- 阶段 5：单元/集成/打包冒烟测试
- 阶段 6：产物收敛 `output/app_desktop/`、安装包验证

**专属验收维度**：

```
桌面交互规范
├── [ ] 窗口/多窗格布局比例明确（原型标注）
├── [ ] 键盘快捷键（如 ⌘K / ⌘,）已定义且可达
├── [ ] 鼠标悬停 / 右键菜单 / 窗口缩放已处理
├── [ ] 桌面端四态齐备（Empty/Loading/Populated/Error）
├── [ ] 菜单栏 / 托盘 / 剪贴板集成已定义
└── [ ] 文件拖放 / 系统对话框集成已定义

打包与分发
├── [ ] 安装包产物重定向至 output/app_desktop/
├── [ ] 安装路径验证通过
├── [ ] 卸载路径验证通过
├── [ ] 自动更新通道可用
├── [ ] 代码签名验证通过
└── [ ] 含原生代码时符号表（dSYM/PDB）成对归档

本地能力
├── [ ] 本地存储（SQLite/文件）读写用例通过
├── [ ] IPC/进程通信用例通过
├── [ ] 离线启动可用
└── [ ] 数据导出/备份用例通过

平台兼容
├── [ ] Windows 目标版本验证通过
├── [ ] macOS 目标版本验证通过
└── [ ] Linux 目标发行版验证通过
```

### P4 移动客户端

**定义**：移动 App / H5 / 小程序，触控优先，有 UI → 原型必产（移动端 390px 形态）。

**典型项目**：iOS/Android App、H5 应用、微信/支付宝小程序。

**代码结构**：`apps/mobile/`（原生可细分 `ios/`、`android/`）；共享契约进 `packages/`。

**影响的关键阶段**：
- 阶段 0：原型必产（移动视口、触控热区、Safe Area、手势）；`DESIGN.md`；视觉签收含移动检查点
- 阶段 1：跨端框架（Flutter/RN/原生）或 H5/小程序栈、打包分发
- 阶段 2：端架构、离线策略
- 阶段 3：本地存储、网络层、六元组
- 阶段 5：真机/模拟器/小程序工具测试
- 阶段 6：产物 `output/app_mobile/`、混淆符号表、商店包验证

**专属验收维度**：

```
移动交互规范
├── [ ] 触控热区 ≥ 44×44px
├── [ ] 底部安全区（Safe Area）处理已定义
├── [ ] 手势返回 / 滑动折叠已定义
├── [ ] 移动端视口断点（375~430px）覆盖
├── [ ] 移动端四态齐备（Empty/Loading/Populated/Error）
└── [ ] 键盘弹起/遮挡表单处理已定义

移动端分发与产物
├── [ ] 安装包重定向至 output/app_mobile/
├── [ ] Android mapping.txt 与安装包成对归档
├── [ ] iOS dSYM 与安装包成对归档
├── [ ] 商店包（IPA/APK/AAB）验证通过
└── [ ] 版本更新/热更新通道可用

移动端质量
├── [ ] 真机冒烟用例通过（核心主路径）
├── [ ] 弱网/断网处理用例通过
├── [ ] 低端机性能基准无劣化
├── [ ] 首屏冷启动时间达标
└── [ ] 后台/恢复状态保持用例通过

平台差异
├── [ ] iOS 目标版本验证通过
├── [ ] Android 目标版本验证通过
└── [ ] （小程序/H5 时）宿主环境验证通过
```

### P5 全端组合

**定义**：多端并存（Web + 移动 + 桌面 + 服务端），共享契约收敛 `packages/`，各端收敛 `apps/<client>/`。

**典型项目**：跨端 SaaS（Web 管理台 + 移动 App + 桌面客户端 + 后端）、多端协同套件。

**代码结构**：`apps/web/`、`apps/mobile/`、`apps/desktop/`、`apps/server/` + `packages/`（共享数据模型/API 契约）+ `config/`。

**影响的关键阶段**：
- 阶段 0：各端分别出原型（形态各异）+ 跨端一致体验（`DESIGN.md` 单一来源）
- 阶段 1：各端技术栈 + 跨端共享方案（Monorepo / 共享 API client）
- 阶段 2：跨端契约层（`packages/`）、端边界
- 阶段 3：共享数据模型/契约先行，各端消费
- 阶段 5：各端测试 + 跨端契约测试
- 阶段 6：各端产物分别收敛 `output/<client>/`

**专属验收维度**：

```
共享契约层（packages/）
├── [ ] 共享数据模型为唯一事实源（packages/）
├── [ ] 共享 API 客户端/契约为单一来源
├── [ ] 各端引用共享契约，无重复定义
└── [ ] 契约版本变更已同步全部消费端

跨端一致性
├── [ ] 跨端行为差异清单已落盘（如桌面快捷键 vs 移动手势）
├── [ ] 跨端登录态一致
├── [ ] 跨端数据同步一致
└── [ ] 各端产物分别收敛于 output/<client>/
```

**组合规则**：验收清单 = **P1 ∪ P2 ∪ P3 ∪ P4 各端专属验收（全量叠加）** + 上述 P5 专属项。

### P6 纯库/包/CLI 工具

**定义**：无部署，交付 SDK / 库 / CLI / 插件，被其它项目引用。

**典型项目**：npm/pip/Maven/Go 模块库、CLI 工具、SDK、共享组件库、插件。

**代码结构**：`packages/` 或独立仓库；无 `apps/*`；若库内带 demo 页面 → 叠加 P2。

**影响的关键阶段**：
- 阶段 0：无 UI 豁免（或 demo 页叠加 P2）；**对外 API 契约先行**（P6 第一公民）
- 阶段 1：语言 / 包管理 / 构建（rollup/tsup/poetry…）、SemVer 策略
- 阶段 2：模块边界、公共 API 面（surface）控制
- 阶段 3：对外契约 / 类型定义、六元组
- 阶段 5：单元测试、兼容性矩阵
- 阶段 6：发布产物、文档、CHANGELOG、包版本

**专属验收维度**：

```
对外契约面（Public API Surface）
├── [ ] 对外导出符号清单已定义
├── [ ] 无意外暴露内部符号
├── [ ] 类型定义（d.ts / 类型文件）随包发布
├── [ ] 破坏性变更遵循 SemVer 主版本
└── [ ] 版本号与 CHANGELOG 同步

构建与发布产物
├── [ ] 构建产物收敛于指定输出目录（dist/…）
├── [ ] 发布包内容校验通过（无源码/密钥泄漏）
├── [ ] 包可被干净安装（安装冒烟通过）
└── [ ] 包元数据（name/version/license）完整

文档与使用
├── [ ] 使用文档（README/API 文档）齐备
├── [ ] 快速上手示例可运行
└── [ ] 破坏性变更迁移指南存在

兼容性
├── [ ] 目标语言/运行时版本矩阵通过
├── [ ] 依赖锁定一致（lockfile 已提交）
└── [ ] 树摇/按需加载验证通过（如适用）
```

## 5. 反模式

| 禁止 | 改为 |
|---|---|
| 清单写合并检查项（"幂等/补偿/fallback 覆盖"） | 拆成原子叶子，各一项 |
| 父节点充当判定项 | 父节点只分组，叶子才判定 |
| 为单个项目从零定制清单 | 套用类型卡 + 基础清单，只记录差异 |
| 类型判定模糊仍继续开发 | 回切 DESIGN 重判类型（或升 M/L） |
| 多端项目只按单一类型验收 | 按组合规则叠加（P5 = P1∪P2∪P3∪P4 + 专属） |
