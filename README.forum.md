# 开源分享：hs-dev-skill，AI 驱动文档，文档驱动代码

大家好，分享一个我在维护的开源项目 **hs-dev-skill**：一套面向 AI 编程助手的 Agent Skill，覆盖需求分析、设计、实现、调试、重构和验收。

核心理念是：**AI 驱动文档，文档驱动代码。** 让 AI 协助形成需求、设计、原型、契约和任务，再依据已确认的文档实现代码，把变更与验证结果持续写回项目记录。

希望做到的是：**开发过程看得见，开发上下文留得住，模型推进有依据。**

项目地址：[GitHub](https://github.com/zhaoxuan-inside/hs-dev-skill)

安装入口：[skills.sh](https://skills.sh/zhaoxuan-inside/hs-dev-skill/hs-dev-skill)

完整下载：[GitHub Releases](https://github.com/zhaoxuan-inside/hs-dev-skill/releases)

## 为什么做这个项目？

用 AI 写代码时，我希望它除了给出实现，还能处理好前后的事情：

- 需求还不明确时，先识别需要确认的问题。
- 修改已有系统时，弄清影响范围，沿用有效设计。
- 修 Bug 时，给出复现、根因和回归验证。
- 任务中断后，能够恢复已有决定和工作断点。
- 宣布完成时，说明做了什么、怎么验证，还有什么没做。

`hs-dev-skill` 尝试把这些要求沉淀成一套可以复用、检查和持续改进的流程。

## 有哪些特点？

**可视化开发过程。** 用需求说明、流程图、架构图、界面原型、任务状态和验收清单展示推进过程。模型如何理解需求、正在做什么、还有哪些问题待确认，都有可以检查的产物。

**持久化开发过程。** 把需求、设计决定、计划、变更日志、快照和验收证据保存在项目文件中。中断、换会话或交接后，可以先恢复已有记录和断点，再继续开发。

**让模型依据文档，减少随意猜测。** 相关文档与契约是实现依据；信息不足时，显式列出假设与待确认项；代码完成后，对照需求和测试证据核对结果。模型推断与开发者已确认的决定分开记录，避免把猜测直接当成业务规则。

整个过程形成一个循环：**AI 整理文档 → 开发者确认关键内容 → 文档指导实现 → 测试与验收核对 → 结果回写文档。**

**按任务选择流程。** 从零开发、Bug 修复、重构、存量项目纳管、只读探索和继续任务分别有对应入口。小改动可以走短路径，复杂变更再补充必要的设计。

**一个主入口，16 个子 Skill。** 主路由协调 10 个过程 Skill 和 6 个功能 Skill，按当前阶段与触达面加载产品、架构、前端、后端、测试等规则，共享脚本和模板。

**把验证依据留在交付里。** 除了流程说明，仓库还包含文档索引、任务状态、过程日志、一致性检查和假代码扫描等工具，以及需求与验收记录模板。

**支持已有项目。** 可以先只读理解代码、梳理现状，也可以围绕一个缺陷或一次重构使用，不必每次都从新项目流程开始。

## 怎么使用？

通过 skills CLI 安装：

```bash
npx skills add zhaoxuan-inside/hs-dev-skill --skill hs-dev-skill
```

安装并加载主 Skill 后，可以这样提需求：

```text
使用 hs-dev-skill，帮我设计一个采购审批工具。
先确认核心场景、MVP 范围和验收标准，再推进设计与实现。
```

也可以用于一个具体问题：

```text
使用 hs-dev-skill，排查订单重复提交的问题。
先复现并定位根因，再做最小修复和回归验证。
```

或者只读了解代码：

```text
使用 hs-dev-skill，只读分析登录鉴权流程，给出证据，不修改文件。
```

请保留完整主包，不要只复制 `SKILL.md`。辅助脚本要求 Python ≥ 3.8；通过 skills CLI 安装需要可运行 `npx` 的 Node.js 环境。详细说明和示例在项目 README 中。

## 适合什么场景？

如果你正在用 AI 维护一个会持续迭代的项目，希望需求、设计、代码和测试能对应起来，可以试试。

项目提供工作流与辅助工具，不能保证自动消除 Bug；实际业务结果仍需要测试和人工评审。开发者需要确认的产品决定，也不会由脚本代签。

项目采用 **MIT 协议**，欢迎试用，也欢迎带着真实场景来提 Issue 或 PR。尤其想了解：哪些流程帮到了你，哪些地方仍然太重，哪些任务容易选错入口。
