## A. 业务语义签收（逐条确认，缺一不可）

- [ ] **核心场景与反目标**：与 PRD 一致，无误解
- [ ] **权限 / 计费 / 归属 / 审计规则**：与预期一致（资料未给则已逐条问清）
- [ ] **核心交互主路径与流程**：路由 / 状态流转无异议
- [ ] **业务规则矩阵与边界异常**：默认值、边界、极端情况符合预期
- [ ] **Gherkin DoD 逐条可测**：Given/When/Then 覆盖主成功流、校验流、异常恢复流
- [ ] **MVP 范围**：MVP 功能边界已由开发者裁定（非 MVP 仅入 MoSCoW 池，不写详细规格）
- [ ] **持久化业务规则（如触达）**：归属、保留、删除与访问规则已确认；新增表 / 改表 / 迁移的物理 DB 设计在阶段 3 必须由开发者决策确认

## B. 视觉签收（有 UI 时，原型 6 项检查）

- [ ] 页面四态无死角（Empty / Loading / Populated / Error）
