# 阶段 0 冻结确认单（{feature_name}）

> 阶段 0 冻结（进入阶段 1 选型）前必须由开发者签署本单。**视觉签收（原型 6 项检查）只代表「好看」，不代表「业务对」——业务语义必须逐条勾选确认。**

## A. 业务语义签收（逐条确认，缺一不可）

- [ ] **核心场景与反目标**：与 PRD 一致，无误解
- [ ] **权限 / 计费 / 归属 / 审计规则**：与预期一致（资料未给则已逐条问清）
- [ ] **核心交互主路径与流程**：路由 / 状态流转无异议
- [ ] **业务规则矩阵与边界异常**：默认值、边界、极端情况符合预期
- [ ] **Gherkin DoD 逐条可测**：Given/When/Then 覆盖主成功流、校验流、异常恢复流
- [ ] **MVP 范围**：MVP 功能边界已由开发者裁定（非 MVP 仅入 MoSCoW 池，不写详细规格）
- [ ] **DB 设计（如触达）**：新增表 / 改表 / 迁移已由开发者决策确认（硬性，不可跳过）

## B. 视觉签收（有 UI 时，原型 6 项检查）

- [ ] 布局与容器结构明确
- [ ] 字体与字阶层级完整（含 tabular-nums）
- [ ] 间距与 Design Tokens 一致
- [ ] 终端平台交互特性合规（桌面/移动/Web）
- [ ] 页面四态无死角（Empty / Loading / Populated / Error）
- [ ] 工程实现可映射（可直接转为组件树 + CSS Variables / Tailwind）

## C. 冻结确认

- [ ] 一源双视图（PRD + vibe_spec）齐套且无语义冲突
- [ ] 分阶段规划书落盘且源自审讯结论（MVP 范围已裁定）
- [ ] Q&A 决策日志（`_03_qa_log/`）已记录关键问答与拍板
