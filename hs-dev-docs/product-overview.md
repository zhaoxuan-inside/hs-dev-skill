# 产品与能力

hs-dev-skill 协调软件工程任务，将用户目标转为可追溯的需求、设计、任务、实现与验证证据。它依赖宿主模型判断语义并执行工程工作，本地 Python 工具负责状态、检索、记录和一致性核验。运行要求为 Python 3.11+ 与 SQLite FTS5。

## 能力与职责

| 层次 | 当前能力 | 结果 |
|---|---|---|
| 总控 | 根据期望结果、范围、已有条件和本轮动作选择过程 | 一个当前主过程及必要专业入口 |
| 过程 | 发现、设计、规划、实现、核验、调试、重构、调查、探索、连续性 | 与本次目标相符的产物、证据和下一动作 |
| 领域 | 产品、前后端与客户端框架、前端各平台、后端、测试、治理 | 所选对象的专业结论或实现 |
| 支撑 | 恢复、完整包更新、可选追踪 | 文件恢复、安装核验或诊断摘要 |
| 运行时 | 工作区协调、任务与依赖、索引与上下文、确认与证据 | 内容版本有效的协作状态 |

## 典型协作

新产品缺少目标和行为时进入 discovery；已有产品契约但缺技术决定时进入 design；设计明确后按需规划或实现。观察到异常先 debugging，保留行为调整结构用 refactoring。解释现状用 exploration，要求重建现状知识用 reverse；续做先 continuity，再回原过程。

每项工作从已有有效成果开始，只补必要缺口。完整产品可逐步覆盖 A～H，局部任务不因此被要求重新走全流程。

## 确认与完成

`stage` 为默认确认模式，开发者按阶段确认；`activity` 按活动人工确认；`mute` 记录模型来源确认。三种模式均需要适用检查和有效证据。trace 默认关闭，独立于确认模式。

测试通过、工作区安全、产物完整和人工确认分别判断。模型不得代签开发者决定；发布受管索引不等于 Git 提交、推送或部署。新增产品规则、生产访问及外部操作仍受本次授权约束。

## 已知边界

意图分类提供候选信号，真实歧义由用户明确；更新入口接收当前完整源包，不自动寻找或下载最新版。语义符号解析当前针对 Python，其他语言支持文件及明确行区间。截图、Mock 与静态审阅的证据不能替代真机、真实服务或实际行为验证。
